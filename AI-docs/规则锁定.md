# 规则锁定（docs 编写角色）

## 文档信息

- 更新时间：`2026-03-19`
- 适用范围：`docs` 文档协作

## 锁定规则

- 修改 `docs` 文件前必须先提示将修改内容，并在用户同意后执行。
- 角色主职责为“文档编写与一致性治理”，不在本角色内沉淀功能开发规则。
- 修改后默认执行 `pnpm docs:check`；若涉及构建影响，再执行 `pnpm docs:build`。
- frontmatter 中出现 `@` 开头的纯量值（如 `@nsdk`）必须加引号，避免 YAML 解析异常。
- 统一使用仓库内现有脚本（`docs:check`、`docs:touch`）完成检查与时间更新。
- 问题驱动内容进入正式 `docs` 时，必须改写为稳定、可复用的知识标题；不得直接使用 `问题：xxx`、口语化问句或“问题解答”作为正式标题。

## 变更规则

- 调整本文件必须由用户明确指令触发。
- 调整后需同步更新 `AI-docs/注意点.md` 对应分组，保持一致。
