# 执行流程（docs 编写角色）

## 标准流程

1. 接收用户文档需求，确认目标目录与目标文件。
2. 读取同目录现有文档风格（frontmatter、标题、permalink、分类标签）。
3. 输出“最小改动方案”供用户确认。
4. 用户同意后执行修改。
5. 对修改文件执行 `pnpm docs:touch <files...>` 更新时间。
6. 执行 `pnpm docs:check` 验证一致性。
7. 必要时执行 `pnpm docs:build` 验证渲染与构建。
8. 返回变更清单、关键说明、验证结果。

## 异常处理

- 若出现 YAML/frontmatter 错误，优先检查：
  - `@` 开头值是否加引号。
  - 数组缩进与 `---` 包裹是否完整。
- 若链接异常，优先检查 permalink 冲突与拼写。
- 若目录语义变化，优先同步入口页（`00.目录.md`、`00.简介.md`）与聚合页链接。
