# 编写标准（docs）

## 目标

- 让文档先能快速理解，再能顺着路径继续深入。
- 让新内容与旧内容保持统一结构，便于长期维护。

## 通用结构

- 入口页优先包含：模块定位、推荐阅读、学习路径、最小理解示例。
- 知识页优先包含：核心目标、表格速查、最小示例、延伸阅读。
- 长文页优先包含：阅读建议，帮助读者先看选型与路径，再看实现细节。
- 前端子模块优先补齐 `00.目录.md`，形成“目录页 + 简介页 + 正文页”的最小体系。

## 内容规则

- 优先写“用途、选型、注意点”，不要一上来堆大段代码。
- 能表格化的内容尽量表格化，例如：类型、分类、策略、对比项。
- 能给最小可执行示例的，尽量给最小示例。
- 专业术语能加高质量外链时，直接补外链。
- 问题驱动内容落文档时，必须整理成稳定知识标题，不直接使用 `问题：xxx`、口语化问句或“问题解答”作为标题。
- 如果需要保留提问语境，只放在正文引导语，不放在文档标题或章节标题。

## 链接规则

- 所有知识类文档默认补 `## 延伸阅读`。
- 延伸阅读优先包含三类：仓库内相关、官方文档、标准/规范。
- 需要时可在正文关键术语处直接补内链或外链。

## 维护规则

- 修改后优先执行 `pnpm docs:touch`。
- 再执行 `pnpm docs:check`。
- 影响渲染或结构时，再执行 `pnpm docs:build`。
