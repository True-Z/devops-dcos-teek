## 核心目标

- 让接口、业务、数据访问各司其职，降低代码耦合。

## 分层速查

| 层级                 | 主要职责           | 不该做什么              |
| -------------------- | ------------------ | ----------------------- |
| Controller / Handler | 接收请求、返回响应 | 不要塞大量业务逻辑      |
| Service              | 组织业务流程       | 不直接处理底层 SQL 细节 |
| Repository / DAO     | 负责数据访问       | 不承载业务规则          |

## 最小示例

```text
Controller 收参数 -> Service 处理业务 -> Repository 查数据库 -> 返回结果
```

- 分层的目的不是“多写文件”，而是让职责更清晰、测试更容易。
