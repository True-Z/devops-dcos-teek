# CSS 渲染性能与重排优化

## 核心目标

- 减少重排/重绘频率，提升页面流畅度与交互响应。

## 优化优先级

| 优先级 | 动作                           | 价值             |
| ------ | ------------------------------ | ---------------- |
| 高     | 减少布局抖动与频繁读写切换     | 直接降低卡顿     |
| 高     | 动画优先 `transform`/`opacity` | 更易走合成层     |
| 中     | 减少大面积样式联动             | 降低连锁重排范围 |
| 中     | 复杂区域分层/分区渲染          | 控制重绘成本     |

## 常见触发源

- 高频修改几何属性（宽高、位置、边距）。
- 频繁读取布局信息并立即写入样式。
- 大量节点在同一帧内同时变更。

## 影响渲染效能的高频问题

| 问题                           | 影响         | 常见场景              |
| ------------------------------ | ------------ | --------------------- |
| 频繁改 `width/height/top/left` | 易触发重排   | 拖拽、动画、列表刷新  |
| 大量阴影/模糊/滤镜             | 绘制成本高   | 卡片阴影、毛玻璃效果  |
| 复杂选择器层级过深             | 匹配成本上升 | 大型页面通用样式      |
| 同步读写布局                   | 造成布局抖动 | 先测量再立刻改样式    |
| 图片尺寸未预留                 | 导致 CLS     | 列表图片、首屏 banner |

## 最小示例

### 不推荐

```js
const height = element.offsetHeight
element.style.height = `${height + 10}px`
```

### 更稳的做法

```js
requestAnimationFrame(() => {
  element.style.transform = 'translateY(10px)'
})
```

- 核心不是永远不用几何属性，而是尽量避免高频同步测量 + 写入的组合。

## 治理建议

- 批量变更样式，减少零散更新。
- 长列表优先虚拟化或分页策略。
- 性能问题先定位瓶颈，再做针对性优化。
