# CSS 速查要点

## 核心目标

- CSS 的本质是“描述呈现”，核心能力是布局、层叠、响应式与动效。
- 排版稳定性优先于花哨效果，优先建立可预测的样式系统；涉及排查可继续看 [CSS BFC 与层叠上下文问题](/fe/css-bfc-stacking-problem) 和 [CSS 渲染性能与重排优化](/fe/css-render-performance)。

## 布局选型建议

| 场景                     | 推荐方案 | 原因                 |
| ------------------------ | -------- | -------------------- |
| 一维排列（横向/纵向）    | Flex     | 语义简单、对齐能力强 |
| 二维网格（行列同时控制） | Grid     | 模板化布局更直观     |
| 文本绕图                 | Float    | 历史兼容场景仍有价值 |
| 吸顶/吸附                | Sticky   | 低成本实现滚动吸附   |

## 层叠与优先级

- 优先通过“选择器设计”解决样式冲突，尽量避免 `!important`。
- 复杂页面建议保持“低权重 + 明确作用域”，避免后期维护失控。
- 先统一命名与作用域，再谈细节样式覆盖。

## 响应式要点

- 先确定主断点（移动端、平板、桌面），再做局部微调。
- 组件优先使用相对单位（`rem`、`%`、`vw/vh`）提升适配弹性。
- 关注“内容断行”和“最小可用宽度”，防止仅视觉缩放。

## 变量与主题要点

- 设计 token 优先沉淀为 CSS 变量，而不是在组件里散落硬编码值。
- 主题切换优先用 `class` 或 `data-theme` 切换，再由 CSS 变量承接真正渲染。
- JS 负责改变量，CSS 负责消费变量。

## 性能与稳定性

- 尽量减少频繁触发重排的属性变更。
- 动画优先使用 `transform` / `opacity`。
- 长列表与复杂页面优先做样式分层与渲染分区。

## 最小示例

```css
.layout {
  display: flex;
  gap: 16px;
}

.sidebar {
  width: 240px;
}

.content {
  flex: 1;
}
```

- 这类写法适合最常见的“侧栏 + 主内容”布局，也是 CSS 在业务中最常见的落地方式。

## 常见误区

- 用固定像素硬撑全端场景，导致适配成本高。
- 把布局问题交给绝对定位堆叠，后续难维护。
- 组件样式未隔离，导致跨页面污染。
