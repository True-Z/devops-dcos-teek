# CSS 动画与过渡选型

## 核心目标

- 先判断该用 `transition` 还是 `animation`，再决定是否要让 JS 参与控制。

## 选型速查

| 场景                  | 推荐方案                | 原因                     |
| --------------------- | ----------------------- | ------------------------ |
| 状态切换型动效        | `transition`            | 简单、声明少、易维护     |
| 持续播放/多关键帧动效 | `animation`             | 能定义更复杂的过程       |
| 与业务逻辑强绑定      | CSS + JS 配合           | 便于控制开始、结束、暂停 |
| 高性能位移动效        | `transform` / `opacity` | 更容易避免重排           |

## 最小示例

### transition

```css
.button {
  transition:
    background-color 0.2s ease,
    transform 0.2s ease;
}

.button:hover {
  background-color: #1677ff;
  transform: translateY(-2px);
}
```

- 适合 hover、激活态、展开收起等“状态变化型”交互。

### animation

```css
@keyframes pulse {
  0% {
    transform: scale(1);
  }
  50% {
    transform: scale(1.05);
  }
  100% {
    transform: scale(1);
  }
}

.badge {
  animation: pulse 1.2s ease-in-out infinite;
}
```

- 适合呼吸、加载、循环提示等持续型动效。

## 常见属性选型

| 属性                    | 是否推荐做动画 | 原因             |
| ----------------------- | -------------- | ---------------- |
| `transform`             | 推荐           | 更容易走合成层   |
| `opacity`               | 推荐           | 变更代价低       |
| `height` / `width`      | 谨慎           | 容易触发重排     |
| `top` / `left`          | 谨慎           | 高频位移代价高   |
| `box-shadow` / `filter` | 谨慎           | 绘制成本可能较高 |

## JS 介入的典型方式

```js
element.classList.add('is-enter')
element.addEventListener('transitionend', () => {
  console.log('transition finished')
})
```

- JS 更适合负责状态切换和事件监听，CSS 负责真正渲染动画。

## 常见误区

- 所有动效都直接上 `animation`，忽略了 `transition` 更简单。
- 高频动画使用 `height/top/left`，导致页面掉帧。
- 动效太多、太快、太花，影响可用性和阅读节奏。
