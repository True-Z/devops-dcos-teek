# CSS 移动端适配清单

## 核心目标

- 把移动端适配从“凭感觉修样式”变成“按清单逐项检查”。

## 基础检查清单

| 检查项     | 关注点                 | 说明               |
| ---------- | ---------------------- | ------------------ |
| 视口设置   | `viewport` 是否正确    | 防止页面缩放异常   |
| 布局方向   | 是否应从多列降为单列   | 防止内容挤压       |
| 点击热区   | 按钮是否足够大         | 防止误触           |
| 字体与行高 | 是否可读               | 防止过密或过小     |
| 横向滚动   | 是否出现意外溢出       | 常见于表格、代码块 |
| 安全区     | 底部是否被系统区域遮挡 | 全面屏设备高频     |

## 最小示例

### 视口

```html
<meta name="viewport" content="width=device-width, initial-scale=1.0" />
```

### 常见移动端按钮区域

```css
.submit-button {
  min-height: 44px;
  padding: 12px 16px;
}
```

- 44px 是常用的触控热区参考线，能显著降低误触概率。

## 常见场景方案

| 场景       | 推荐方案                      | 说明                     |
| ---------- | ----------------------------- | ------------------------ |
| 表格过宽   | 外层加横向滚动容器            | 优先保证可读，不强行压缩 |
| 双列卡片   | 小屏退化成单列                | 更稳定                   |
| 固定底栏   | 预留 `safe-area-inset-bottom` | 适配全面屏               |
| 文本过长   | 多行省略或折行策略            | 防止撑坏布局             |
| Hover 交互 | 提供触摸等价反馈              | 移动端没有真正 hover     |

## 常见问题

- 页面看起来缩小，但其实只是浏览器缩放，不是真正适配。
- 按钮视觉好看但点击区域过小。
- 只调字号，不调间距和层级，导致整体仍难读。
- 忽略代码块、表格、长链接带来的横向滚动。

## 发布前速查

1. 真机查看，而不只看浏览器响应式面板。
2. 检查首屏、表单、弹层、底部按钮。
3. 检查横屏、全面屏、安全区。
4. 检查长列表、表格、代码块、图片。
