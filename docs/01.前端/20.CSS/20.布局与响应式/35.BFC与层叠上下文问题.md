# CSS BFC 与层叠上下文问题

## 什么是 BFC

- BFC（Block Formatting Context，块级格式化上下文）可以理解为一个独立的块级布局区域。
- 这个区域内部的盒子布局会按自己的规则计算，外部元素不会直接参与内部浮动和垂直 margin 的计算。
- 它本质上是浏览器为“隔离布局影响”设计的一套机制。

## 常见触发方式

| 方式                    | 示例                    | 常见用途                        |
| ----------------------- | ----------------------- | ------------------------------- |
| `overflow` 非 `visible` | `overflow: hidden`      | 清除浮动、裁剪溢出              |
| `display: flow-root`    | `display: flow-root`    | 现代、语义更清晰的 BFC 触发方式 |
| `float`                 | `float: left`           | 浮动元素本身会形成 BFC          |
| 绝对/固定定位           | `position: absolute`    | 脱离普通文档流                  |
| `inline-block`          | `display: inline-block` | 行内块布局隔离                  |

## BFC 的作用

- 隔离布局影响，减少“相互干扰”。
- 典型用途：清除浮动、阻止外边距合并、控制溢出布局。

## 层叠上下文的作用

- 决定元素的堆叠顺序，不是简单比 `z-index` 数值大小。
- `z-index` 失效多数是“比较发生在不同层叠上下文”；可继续看 [MDN Stacking context](https://developer.mozilla.org/en-US/docs/Web/CSS/CSS_positioned_layout/Stacking_context)。

## 排查口诀

- 先看是否创建了新的层叠上下文。
- 再看目标元素与参照元素是否在同一上下文。
- 最后再调 `z-index` 数值。

## 最小示例

### BFC 清除浮动

```css
.wrapper {
  overflow: hidden;
}

.item {
  float: left;
}
```

- `overflow: hidden` 会触发 [BFC](https://developer.mozilla.org/zh-CN/docs/Web/Guide/CSS/Block_formatting_context)，父元素就能重新计算浮动子元素高度。

### `z-index` 不生效的常见场景

```css
.parent {
  position: relative;
  z-index: 1;
}

.child {
  position: absolute;
  z-index: 9999;
}

.mask {
  position: fixed;
  z-index: 2;
}
```

- 即使 `.child` 的 `z-index` 很大，它仍受 `.parent` 所在层叠上下文约束，未必能盖过 `.mask`。

## 常见误区

- 把所有遮罩问题都归因于 `z-index` 太小。
- 为了修一个问题，到处加定位和层级，导致后续更难维护。
