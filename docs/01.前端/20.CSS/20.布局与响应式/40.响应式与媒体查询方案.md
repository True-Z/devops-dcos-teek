# CSS 响应式与媒体查询方案

## 核心目标

- 在不同屏幕尺寸下保持信息层级稳定与交互可用。

## 策略建议

| 维度     | 建议                   | 说明           |
| -------- | ---------------------- | -------------- |
| 断点设计 | 先主断点，再局部微调   | 减少样式碎片化 |
| 单位选择 | 相对单位优先           | 便于缩放与适配 |
| 布局方式 | Flex/Grid 优先         | 可维护性更高   |
| 内容策略 | 先保证可读，再优化美观 | 防止挤压与溢出 |

## 移动优先与桌面优先

| 策略     | 写法特点                                    | 适合场景                           |
| -------- | ------------------------------------------- | ---------------------------------- |
| 移动优先 | 先写小屏基础样式，再用 `min-width` 往上增强 | 新项目、组件化项目、现代响应式站点 |
| 桌面优先 | 先写桌面样式，再用 `max-width` 向下兼容     | 旧 PC 站改造、已有大屏样式体系     |

- 平板通常只是“中间断点”，不是最常见的优先策略名。

## `min-width` 与 `max-width` 选型

| 条件                 | 推荐搭配     | 原因                               |
| -------------------- | ------------ | ---------------------------------- |
| 新项目               | `min-width`  | 更贴近移动优先思路，增强路径更自然 |
| 已有桌面站改造移动端 | `max-width`  | 先保留桌面样式，再向下覆盖更顺手   |
| 断点较多且层级复杂   | 统一只选一种 | 降低维护混乱                       |

### `min-width` 示例

```css
.layout {
  grid-template-columns: 1fr;
}

@media (min-width: 768px) {
  .layout {
    grid-template-columns: 1fr 1fr;
  }
}
```

### `max-width` 示例

```css
.layout {
  grid-template-columns: repeat(3, 1fr);
}

@media (max-width: 768px) {
  .layout {
    grid-template-columns: 1fr;
  }
}
```

- 推荐默认结论：新项目优先“移动优先 + `min-width`”，桌面改造项目再考虑 `max-width`。

## 常见断点速查

| 场景 | 建议范围         | 用途                           |
| ---- | ---------------- | ------------------------------ |
| 手机 | `< 768px`        | 单列、紧凑布局、按钮优先可触达 |
| 平板 | `768px ~ 1024px` | 过渡布局、局部双列             |
| 桌面 | `> 1024px`       | 多列布局、更多辅助信息         |

- 断点没有绝对标准，核心是围绕内容断裂点调整，而不是死记某个宽度。

## 常用媒体特性

| 媒体特性                 | 作用         | 常见场景             |
| ------------------------ | ------------ | -------------------- |
| `width` / `max-width`    | 按宽度适配   | 手机、平板、桌面断点 |
| `orientation`            | 横竖屏区分   | 平板、移动端横屏     |
| `hover`                  | 是否支持悬浮 | 区分鼠标端和触控端   |
| `pointer`                | 指针精度     | 区分粗指针和细指针   |
| `prefers-color-scheme`   | 系统主题偏好 | 明暗模式             |
| `prefers-reduced-motion` | 动画偏好     | 无障碍与减动效       |

## 客户端 / 手机端常用方案

| 场景             | 推荐方案                      | 说明                  |
| ---------------- | ----------------------------- | --------------------- |
| 列表从多列变单列 | `grid/flex` + `max-width`     | 最常见                |
| 表格过宽         | 横向滚动容器                  | 比强行压缩更稳        |
| 底部固定按钮     | `sticky/fixed` + 安全区       | 手机端表单高频        |
| 刘海屏适配       | `env(safe-area-inset-bottom)` | 避免底部内容被遮挡    |
| 仅触摸设备优化   | `@media (hover: none)`        | 关闭无意义 hover 交互 |

## 关键检查项

- 文案是否换行可读。
- 表格与长内容是否有降级展示策略。
- 关键操作按钮在移动端是否可触达。

## 最小示例

### 媒体查询

```css
.card-list {
  display: grid;
  grid-template-columns: repeat(3, 1fr);
  gap: 16px;
}

@media (max-width: 768px) {
  .card-list {
    grid-template-columns: 1fr;
  }
}
```

- 桌面端 3 列，移动端退化为单列，这是最常见也最稳定的响应式写法。

### 相对单位

```css
.title {
  font-size: 1.125rem;
  padding: 0.75rem 1rem;
}
```

- `rem` 更适合跟随根字号缩放，比全用固定 `px` 更容易维护。

### 客户端/手机端底部安全区

```css
.footer-action {
  padding-bottom: calc(16px + env(safe-area-inset-bottom));
}
```

- 适合全面屏设备，避免底部操作按钮被系统手势区域遮挡。

## 常见误区

- 只做宽度缩放，不做内容结构调整。
- 断点过多导致维护成本上升。
- 只照顾桌面效果，忽略移动端点击热区与内容层级。
