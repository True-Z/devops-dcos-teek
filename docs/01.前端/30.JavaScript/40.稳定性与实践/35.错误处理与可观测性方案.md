# JavaScript 错误处理与可观测性方案

## 核心目标

- 让错误“可发现、可定位、可恢复”，而不是静默失败。

## 模块定位

- 这页重点是“线上可维护性”，适合和接口调用、埋点、日志体系一起看。

## 错误分层

| 层级   | 典型错误                 | 处理建议           |
| ------ | ------------------------ | ------------------ |
| 业务层 | 参数不合法、状态不满足   | 给出可执行提示     |
| 网络层 | 超时、断网、网关错误     | 重试/降级/兜底     |
| 运行时 | 未捕获异常、Promise 拒绝 | 统一上报与边界保护 |

## 最小示例

### 统一错误包装

```js
function createBizError(message, code, extra = {}) {
  return {
    name: 'BizError',
    message,
    code,
    ...extra,
  }
}
```

- 这样可以统一错误结构，便于页面提示、日志上报和问题检索。

### 异步错误处理

```js
try {
  const data = await fetchUser()
  return data
} catch (error) {
  reportError(error)
  showMessage('获取用户信息失败，请稍后重试')
}
```

- 关键点是“记录错误 + 给用户反馈”，而不是只在控制台打印。

## 可观测性最小集

- 错误日志：错误类型、上下文、用户动作路径。
- 性能指标：请求耗时、页面关键耗时、长任务。
- 业务指标：成功率、重试率、失败分布。

## 常见错误处理策略

| 场景           | 建议策略          | 说明                   |
| -------------- | ----------------- | ---------------------- |
| 表单校验失败   | 就地提示          | 让用户立即知道怎么改   |
| 接口短暂失败   | 限次重试          | 防止偶发网络问题放大   |
| 权限失效       | 跳转登录/刷新令牌 | 统一处理会话过期       |
| 未知运行时错误 | 上报 + 兜底页     | 先保留现场，再降低影响 |

## 实施建议

- 统一错误对象结构，避免到处自定义。
- 关键流程必须有失败兜底与用户提示。
- 线上问题优先“定位链路”而非盲目修补；相关术语可继续阅读 [Error](https://developer.mozilla.org/zh-CN/docs/Web/JavaScript/Reference/Global_Objects/Error)、[try...catch](https://developer.mozilla.org/zh-CN/docs/Web/JavaScript/Reference/Statements/try...catch)。
