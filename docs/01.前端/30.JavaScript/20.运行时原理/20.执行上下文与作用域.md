# JavaScript 执行上下文与作用域

## 核心目标

- 理解代码为什么能访问某些变量、`this` 为什么会变、闭包为什么还能拿到外层值。

## 核心概念速查

| 概念       | 作用                 | 关注点               |
| ---------- | -------------------- | -------------------- |
| 执行上下文 | 代码运行时的环境     | 全局、函数、`eval`   |
| 作用域     | 标识符可访问范围     | 静态作用域、词法环境 |
| 执行栈     | 管理函数调用顺序     | 入栈、出栈           |
| 闭包       | 保留外层词法环境引用 | 内存占用、状态封装   |

## 最小示例

```js
function outer() {
  const name = 'tom'

  return function inner() {
    return name
  }
}
```

- `inner` 执行时仍能访问 `name`，本质上就是闭包保留了外层词法环境。

## 执行上下文怎么理解

- 全局代码先进入全局执行上下文。
- 每次函数调用，都会创建新的函数执行上下文并压入执行栈。
- 当前栈顶上下文执行结束后出栈，控制权回到下一个上下文。

## `this` 的核心规则

| 场景              | `this` 指向                                       |
| ----------------- | ------------------------------------------------- |
| 普通函数直接调用  | 浏览器中通常是 `window`，严格模式下是 `undefined` |
| 对象方法调用      | 指向调用它的对象                                  |
| `call/apply/bind` | 显式指定对象                                      |
| 箭头函数          | 不创建自己的 `this`，取外层                       |

## 变量提升与闭包

### 变量提升是什么

- 变量提升不是“代码真的移动到了上面”，而是创建执行上下文时，声明会先被处理。
- `var` 会被提升并初始化为 `undefined`。
- `function` 声明通常会连同函数体一起提前可用。
- `let`、`const` 也会提升，但在声明前处于暂时性死区。

```js
console.log(a) // undefined
var a = 1
```

```js
console.log(b) // ReferenceError
let b = 1
```

### 闭包是什么

- 闭包不是特殊语法，而是“函数持有并访问其定义时所在词法环境”的现象。
- 只要函数在其定义位置之外执行，但仍然能访问外层变量，本质上就是闭包。

```js
function createCounter() {
  let count = 0

  return function increment() {
    count += 1
    return count
  }
}
```

### 闭包有什么作用

| 作用                     | 典型场景                 |
| ------------------------ | ------------------------ |
| 保留状态                 | 计数器、缓存、once 函数  |
| 封装变量                 | 避免外部直接改内部数据   |
| 延迟执行时继续访问上下文 | 回调、事件处理、异步流程 |

### 常见追问

- 闭包不是天然性能问题，问题在于“不必要地长期引用大对象”。
- 变量提升与作用域要分开看：作用域解决“在哪里能访问”，提升解决“在当前作用域里什么时候能被感知”。

## 常见误区

- 把 `this` 当成“定义时决定”，实际上普通函数多数取决于调用方式。
- 把闭包当成“高级技巧”，但不注意长期引用导致内存问题。
- 混淆“变量提升”和“作用域”。

## 变量提升与作用域的区分

### 为什么容易混淆

- 两者都会影响“变量为什么能访问 / 为什么不能访问”。
- 它们都发生在代码真正执行前后的同一套上下文里，初学时很容易看成同一件事。
- 典型表现是：把“提前能不能访问”误以为是作用域问题，其实很多时候是提升问题。

### 本质区别

| 概念     | 解决什么问题                   | 关键词 |
| -------- | ------------------------------ | ------ |
| 作用域   | 变量在哪些位置可访问           | 范围   |
| 变量提升 | 声明在当前作用域内何时可被感知 | 时机   |

- 作用域回答的是：`这个变量归谁管，在哪一层能访问到？`
- 提升回答的是：`在当前作用域里，这个声明在执行前是怎样被处理的？`

### 如何区分

#### 先看是不是“访问范围”问题

```js
function test() {
  const name = 'tom'
}

console.log(name)
```

- 这里报错，核心是 `name` 不在当前作用域可访问范围内。

#### 再看是不是“声明时机”问题

```js
console.log(a)
var a = 1
```

- 这里能访问到 `a`，但值是 `undefined`，核心是 `var` 声明被提升了。

```js
console.log(b)
let b = 1
```

- 这里报错，不是因为没有作用域，而是因为 `let` 在提升后处于暂时性死区。

### 一句话记忆

- 作用域看“在哪里能访问”。
- 提升看“在当前作用域里，声明什么时候生效”。
