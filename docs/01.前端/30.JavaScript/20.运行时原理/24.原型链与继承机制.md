# JavaScript 原型链与继承机制

## 核心目标

- 理解对象属性为什么能“向上找”，以及类继承背后到底发生了什么。

## 阅读建议

- 先分清 `prototype`、`__proto__`、`constructor` 三者职责，再看继承写法，不然很容易把“对象之间的链路”和“函数本身的链路”混在一起。
- 这页偏运行时原理，不是语法糖说明书；如果你更关心工程里怎么组织异步，请去看 [JavaScript 异步并发方案](/fe/javascript-async-concurrency)。

## 核心概念速查

| 概念     | 含义                                    | 关注点                           |
| -------- | --------------------------------------- | -------------------------------- |
| 显式原型 | 函数的 `prototype` 属性                 | 给实例提供共享方法               |
| 隐式原型 | 对象内部的 `[[Prototype]]`              | 属性查找链路                     |
| 原型链   | 一层层沿 `[[Prototype]]` 向上查找的链路 | 查找顺序、遮蔽、终点             |
| 继承     | 复用父级能力的机制                      | `Object.create`、构造函数、class |
| 构造函数 | 用来初始化实例的函数                    | `new`、实例属性                  |
| 原型方法 | 放在原型上的共享方法                    | 节省内存、共享行为               |

## 最小理解图

```text
实例对象
  -> __proto__ 指向 构造函数.prototype
  -> prototype 上再通过 __proto__ 向上连接
  -> 最终到 Object.prototype
  -> 再到 null 结束
```

- 你可以把原型链理解成“对象查找属性时的备用路径”。

## 最小示例

```js
function Animal(name) {
  this.name = name
}

Animal.prototype.eat = function () {
  return `${this.name} is eating`
}

const dog = new Animal('Lucky')

dog.bark = () => 'wang'
```

- `dog` 自己没有 `eat` 时，会沿着原型链去 `Animal.prototype` 查找。

## 三个最容易混淆的概念

| 名称          | 挂在谁身上         | 作用                         |
| ------------- | ------------------ | ---------------------------- |
| `prototype`   | 函数对象           | 作为未来实例的共享原型对象   |
| `__proto__`   | 几乎所有对象实例上 | 指向当前对象的上层原型       |
| `constructor` | 原型对象上         | 记录该原型默认关联的构造函数 |

```js
function Person() {}

const p = new Person()

console.log(p.__proto__ === Person.prototype) // true
console.log(Person.prototype.constructor === Person) // true
```

- `prototype` 是“函数给实例准备的原型对象”。
- `__proto__` 是“某个对象当前沿哪条链继续往上找”。
- `constructor` 更像一条默认回指信息，方便识别原型原本属于哪个构造函数。

## 属性查找是怎么发生的

1. 先查对象自身属性。
2. 自身没有，就沿 `__proto__` 向上找。
3. 一直找到 `Object.prototype`。
4. 再往上到 `null` 结束，仍然没有就是 `undefined`。

```js
const parent = { a: 1 }
const child = Object.create(parent)

child.b = 2

console.log(child.a) // 1
console.log(child.b) // 2
```

- `a` 不在 `child` 自身上，但在它的原型对象 `parent` 上。

## 什么是属性遮蔽

```js
const parent = { name: 'parent' }
const child = Object.create(parent)

child.name = 'child'
console.log(child.name) // child
```

- 这不是修改了父级属性，而是子对象自身新增了同名属性，把向上查找的结果“挡住”了。

## `new` 到底做了什么

```js
function User(name) {
  this.name = name
}

const u = new User('tom')
```

可以近似理解成 4 步：

1. 创建一个新对象。
2. 把新对象的隐式原型指向 `User.prototype`。
3. 用这个新对象作为 `this` 执行 `User`。
4. 如果没有手动返回对象，就返回这个新对象。

## 为什么方法要挂在原型上

```js
function User(name) {
  this.name = name
}

User.prototype.sayHi = function () {
  return `hi, ${this.name}`
}
```

- 实例属性适合放“每个实例都不同的数据”。
- 原型方法适合放“所有实例共享的行为”。
- 如果把方法都写进构造函数内部，每 new 一次就会重新创建一份函数对象。

## 构造函数继承和原型继承怎么配合

```js
function Animal(name) {
  this.name = name
}

Animal.prototype.eat = function () {}

function Dog(name, breed) {
  Animal.call(this, name)
  this.breed = breed
}

Dog.prototype = Object.create(Animal.prototype)
Dog.prototype.constructor = Dog
Dog.prototype.bark = function () {}
```

- `Animal.call(this, name)` 负责继承实例属性。
- `Object.create(Animal.prototype)` 负责继承原型方法。
- `constructor` 手动指回 `Dog`，让原型对象关系更完整。

## `class extends` 的本质

```js
class Animal {
  constructor(name) {
    this.name = name
  }

  eat() {}
}

class Dog extends Animal {
  bark() {}
}
```

- `class` 不是一套全新的继承模型，而是对原型继承更清晰的语法封装。
- 实例仍然沿原型链查找方法。
- `extends` 本质上还是把 `Dog.prototype` 连接到 `Animal.prototype`。

## 两条链不要混淆

### 1. 实例对象的原型链

```text
dog -> Dog.prototype -> Animal.prototype -> Object.prototype -> null
```

### 2. 构造函数对象本身的链

```text
Dog -> Function.prototype -> Object.prototype -> null
```

- 第一条链解决“实例怎么找属性和方法”。
- 第二条链解决“函数对象自己也是对象，它往哪条链找”。
- 很多人会乱，是因为把“函数作为构造器”与“函数作为对象”两种身份混在一起了。

## 继承怎么理解

- 继承不是“复制父类一份代码”，而是建立一条可复用的对象查找链路。
- 构造函数主要负责初始化实例属性。
- 原型主要负责共享方法。
- `class extends` 只是更现代的写法，本质仍然是对象之间的原型继承。

## 常见误区

- 以为 `class` 是另一套完全不同的继承机制。
- 把所有方法都写进实例，浪费内存。
- 不理解属性查找顺序，排查问题时很迷糊。
- 把 `prototype` 和 `__proto__` 当成同一个东西。
- 忘记 `Dog.prototype = Object.create(Animal.prototype)` 后把 `constructor` 指回去。
