# JavaScript 事件循环与异步机制

## 核心目标

- 理解为什么同步代码先执行、为什么微任务会更早执行、为什么 UI 有时会卡住。

## 模块定位

- 这页放在“运行时原理”，因为它解释的是 JavaScript 与宿主环境如何调度任务，也就是“为什么会这样执行”。
- 如果你更关心异步任务怎么组织、限流、重试、并发控制，请去看 [JavaScript 异步并发方案](/fe/javascript-async-concurrency)。

## 核心概念速查

| 概念     | 含义                           | 关注点                           |
| -------- | ------------------------------ | -------------------------------- |
| 宏任务   | 一轮事件循环中的大任务         | `setTimeout`、I/O、UI 事件       |
| 微任务   | 当前宏任务结束后立即清空的任务 | `Promise.then`、`queueMicrotask` |
| 事件循环 | 调度任务执行的机制             | 执行顺序、渲染时机               |

## 最小示例

```js
console.log(1)

setTimeout(() => console.log(2))

Promise.resolve().then(() => console.log(3))

console.log(4)
```

- 输出通常是 `1 4 3 2`，核心原因是：同步代码先执行，微任务早于下一轮宏任务。

## 最常见的理解顺序

1. 先执行当前同步代码。
2. 当前宏任务结束后，清空微任务队列。
3. 必要时浏览器进行渲染。
4. 进入下一轮宏任务。

## 宏任务、微任务与调度归类

### 如何区分

- 宏任务可以理解为“一轮事件循环中的主任务单元”。
- 微任务可以理解为“当前宏任务结束后、进入下一轮宏任务前必须清空的任务”。
- 在浏览器里，常见顺序是：同步代码 -> 微任务 -> 必要时渲染 -> 下一轮宏任务。

### 常见宏任务

| 类型     | 常见方法/来源                            | 说明                 |
| -------- | ---------------------------------------- | -------------------- |
| 定时器   | `setTimeout` `setInterval`               | 到时后进入宏任务队列 |
| UI 事件  | click、input、scroll 等事件回调          | 由宿主环境派发       |
| 网络/I-O | XHR/fetch 的后续回调、I/O 完成通知       | 由宿主环境调度       |
| 消息通信 | `postMessage`、`MessageChannel` 某些回调 | 依赖宿主实现         |

### 常见微任务

| 类型     | 常见方法/来源            | 说明             |
| -------- | ------------------------ | ---------------- |
| Promise  | `then` `catch` `finally` | 最常见微任务来源 |
| 显式入队 | `queueMicrotask`         | 手动插入微任务   |
| 观察器   | `MutationObserver`       | DOM 变更观察回调 |

### 常见追问

- `setTimeout(fn, 0)` 不是立即执行，而是“最早下一轮宏任务再执行”。
- `Promise.then()` 比 `setTimeout()` 更早，原因不是“优先级更高”，而是它属于当前宏任务结束后的微任务清空阶段。
- 微任务过多也会卡渲染，因为它会在进入下一轮宏任务前持续被清空。

## 最小判断题

```js
console.log('start')

setTimeout(() => console.log('timeout'))

queueMicrotask(() => console.log('microtask'))

Promise.resolve().then(() => console.log('promise'))

console.log('end')
```

- 常见输出是：`start` -> `end` -> `microtask` -> `promise` -> `timeout`。
- `queueMicrotask` 和 `Promise.then` 都属于微任务，先后取决于入队顺序。

## 常见误区

- 认为 `setTimeout(fn, 0)` 就是“立刻执行”。
- 把所有异步回调都当成同一优先级。
- 在微任务里塞太多工作，导致渲染饥饿。
