# 正则表达式学习记录

## 阅读建议

- 这页重点不是一次学全正则，而是先让人看到一个表达式时，能大致知道它在匹配什么。

## 核心目标

- 建立最小正则认知：常见符号、组合方式、怎么读、怎么验证。

## 正则是什么

- 正则表达式可以理解成“字符串匹配规则”。
- 它常用于校验、搜索、提取和替换。

## 常见符号速记

| 符号 | 含义           | 最小示例 |
| ---- | -------------- | -------- |
| `.`  | 任意单个字符   | `a.c`    |
| `\d` | 数字           | `\d+`    |
| `\w` | 字母数字下划线 | `\w+`    |
| `*`  | 0 次或多次     | `ab*`    |
| `+`  | 1 次或多次     | `ab+`    |
| `?`  | 0 次或 1 次    | `ab?`    |
| `[]` | 字符集合       | `[abc]`  |
| `^`  | 开头           | `^abc`   |
| `$`  | 结尾           | `abc$`   |

## 怎么读一个正则

| 表达式          | 怎么理解                           |
| --------------- | ---------------------------------- |
| `^abc$`         | 整个字符串就是 `abc`               |
| `^\d+$`         | 整个字符串只能由数字组成           |
| `^[a-zA-Z]+$`   | 整个字符串只能由字母组成           |
| `^1[3-9]\d{9}$` | 以 1 开头，第二位 3 到 9，共 11 位 |

## 最小示例

```js
/^\d+$/
/^[a-zA-Z]+$/
/^1[3-9]\d{9}$/
```

## 常见场景

| 场景   | 正则思路                             |
| ------ | ------------------------------------ |
| 纯数字 | `^\d+$`                              |
| 纯字母 | `^[a-zA-Z]+$`                        |
| 手机号 | `^1[3-9]\d{9}$`                      |
| 邮箱   | 先从基础结构理解，不急着上超长表达式 |

## 常用校验例子速查表

| 场景        | 示例正则                                 | 说明                           |
| ----------- | ---------------------------------------- | ------------------------------ | ------------------- |
| 用户名      | `^[a-zA-Z0-9_]{4,16}$`                   | 4 到 16 位，字母数字下划线     |
| 密码        | `^(?=.*[A-Za-z])(?=.*\d)[A-Za-z\d]{8,}$` | 至少 8 位，至少有字母和数字    |
| 手机号      | `^1[3-9]\d{9}$`                          | 常见中国大陆手机号格式         |
| 邮箱        | `^[^\s@]+@[^\s@]+\.[^\s@]+$`             | 先理解基本结构即可             |
| 身份证号    | `^\d{17}[\dXx]$`                         | 只做基础格式校验               |
| URL         | `^https?:\/\/[^\s]+$`                    | 只校验最基础的 http/https 结构 |
| 中文        | `^[\u4e00-\u9fa5]+$`                     | 只包含中文字符                 |
| HTML 颜色值 | `^#([0-9a-fA-F]{3}                       | [0-9a-fA-F]{6})$`              | `#fff` 或 `#ffffff` |

## 使用提醒

- 正则更适合先做“格式校验”，不等于完整业务校验。
- 像邮箱、URL、身份证这类复杂场景，通常先做基础校验就够。
- 业务里优先保证“可读、够用、方便维护”，不要一味追求超长正则。

## 常见误区

- 一上来就背特别长的正则。
- 只记结果，不知道每个符号在干什么。
- 看到正则就怕，其实它本质是“规则组合”。
