# JavaScript 柯里化与函数式编程

## 阅读建议

- 这页重点不是讲抽象概念，而是理解柯里化和函数式编程在业务里到底有什么用。

## 核心目标

- 看完后能知道：什么是柯里化、函数式编程在强调什么、为什么它们在 JavaScript 里有实际价值。

## 柯里化是什么

- 柯里化可以理解成：把一个接收多个参数的函数，拆成一连串每次只接收一个参数的函数。

## 最小示例

```js
const add = (a) => (b) => a + b

add(1)(2) // 3
```

## 柯里化有什么用

| 作用       | 说明                         |
| ---------- | ---------------------------- |
| 参数复用   | 先固定一部分参数，后面重复用 |
| 逻辑拆分   | 把大函数拆成更小的处理步骤   |
| 更容易组合 | 和其他函数拼起来更自然       |

## 函数式编程在讲什么

- 函数式编程不是“只准写函数”。
- 更重要的是这些思路：
  - 输入输出清晰
  - 少副作用
  - 尽量做纯函数
  - 把复杂处理拆成可组合的小函数

## 最小纯函数示例

```js
function double(n) {
  return n * 2
}
```

- 给定同样输入，永远返回同样输出，这类函数更容易测试和复用。

## 如何实现柯里化

### 手写最小版

```js
function curry(fn) {
  return function curried(...args) {
    if (args.length >= fn.length) {
      return fn(...args)
    }
    return (...rest) => curried(...args, ...rest)
  }
}
```

## 具体使用方案

| 场景     | 做法                           |
| -------- | ------------------------------ |
| 日志函数 | 先固定日志级别，再传内容       |
| 校验函数 | 先固定规则，再校验具体值       |
| 数据处理 | 把过滤、转换、格式化拆成小函数 |

## `compose` 和 `pipe`

- 两者本质上都是“把多个小函数串起来”。
- 区别主要在执行方向。

| 工具      | 执行方向 | 更直观理解         |
| --------- | -------- | ------------------ |
| `compose` | 从右到左 | 先执行最后一个函数 |
| `pipe`    | 从左到右 | 按书写顺序一步步走 |

## 最小实现

```js
const compose =
  (...fns) =>
  (value) =>
    fns.reduceRight((acc, fn) => fn(acc), value)

const pipe =
  (...fns) =>
  (value) =>
    fns.reduce((acc, fn) => fn(acc), value)
```

## 最小示例

```js
const add1 = (n) => n + 1
const double = (n) => n * 2

compose(double, add1)(1) // 4
pipe(add1, double)(1) // 4
```

## 什么时候更适合用 `pipe`

- 数据流是一步一步向前处理时。
- 你希望阅读顺序和执行顺序一致时。

## 什么时候更适合用 `compose`

- 你已经习惯把函数从结果往回组装时。
- 某些函数式库本身就是 `compose` 风格时。

## 应用场景

| 场景         | 为什么适合                      |
| ------------ | ------------------------------- |
| 表单校验     | 规则可复用，参数可预先固定      |
| 列表数据处理 | 过滤、映射、排序可拆开组合      |
| 工具函数     | 小函数更容易复用和测试          |
| 数据加工链   | `pipe` / `compose` 串起多个步骤 |

## 常见误区

- 看到柯里化就觉得高级，实际上很多业务不一定需要。
- 为了函数式而函数式，反而把代码写复杂。
- 纯函数和无副作用没分清，导致概念混乱。
