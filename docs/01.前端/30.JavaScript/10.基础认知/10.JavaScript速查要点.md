# JavaScript 速查要点

## 核心定位

- JavaScript 负责页面行为、状态管理与业务逻辑组织。
- 真实开发中，性能问题多数来自“数据流与异步流”而非语法本身；延伸可继续看 [JavaScript 异步并发方案](/fe/javascript-async-concurrency)、[JavaScript 错误处理与可观测性方案](/fe/javascript-error-observability)。

## 认知主线

| 主题       | 关注点               | 为什么重要               |
| ---------- | -------------------- | ------------------------ |
| 执行上下文 | 作用域、`this`、闭包 | 决定变量可见性与调用行为 |
| 事件循环   | 宏任务/微任务顺序    | 影响异步时序与 UI 响应   |
| 原型链     | 对象复用与继承       | 影响对象模型与性能       |
| 垃圾回收   | 可达性与生命周期     | 影响内存与卡顿           |

## 异步策略速记

- 并发控制优先考虑“失败策略”和“限流策略”。
- Promise 组合方法按语义使用：全成功、先完成、全结果、先成功。
- async/await 适合线性业务流，但要显式处理异常边界。

## 类型与边界

- 输入边界先校验，再进入核心逻辑。
- 类型判断避免只依赖 `typeof`，应结合场景判断对象与数组。
- 统一错误对象结构，便于日志与问题排查。

## 最小示例

```js
async function loadUser(id) {
  if (!id) throw new Error('id required')

  const data = await fetchUser(id)
  return data
}
```

- 这个示例体现了 JavaScript 业务代码的三件事：输入校验、异步处理、明确返回值。

## 常见误区

- 把所有逻辑塞进一个函数，导致可测试性差。
- 微任务滥用导致渲染饥饿。
- 闭包引用长期对象导致内存泄漏。

## 实施建议

- 先设计数据流，再写函数细节。
- 对外暴露 API 时先定输入输出契约。
- 高频逻辑优先做可观测（耗时、错误率、重试次数）。
