# JavaScript 异步并发方案

## 核心目标

- 在保证结果正确的前提下，控制请求并发量与失败影响范围。

## 模块定位

- 这页解决的是“异步任务怎么组织更稳”，偏工程方案而不是语言底层原理。
- 事件循环、宏任务、微任务这些底层调度规则不在这页展开，统一放在 [JavaScript 事件循环与异步机制](/fe/javascript-event-loop) 里讲。

## 常见策略

| 策略     | 适用场景       | 关键点                 |
| -------- | -------------- | ---------------------- |
| 串行     | 强依赖步骤流程 | 结果稳定但耗时更长     |
| 并行     | 互不依赖任务   | 提升速度但需控失败影响 |
| 限流并发 | 批量任务处理   | 控制资源占用峰值       |
| 重试退避 | 短暂失败场景   | 避免雪崩与放大流量     |

## Promise 组合选型

- 全部成功才继续：用“全量成功”策略。
- 不希望单点失败中断：用“全量结果”策略。
- 抢最快成功结果：用“先成功返回”策略。

## 最小示例

### 串行

```js
await taskA()
await taskB()
await taskC()
```

- 适合强依赖流程：上一步结果决定下一步输入。

### 并行

```js
await Promise.all([taskA(), taskB(), taskC()])
```

- 适合互不依赖的任务；其中一个失败会整体失败。

### 限流并发

```js
const queue = [...tasks]
const workers = Array.from({ length: 3 }, async () => {
  while (queue.length) {
    const task = queue.shift()
    await task?.()
  }
})

await Promise.all(workers)
```

- 适合批量请求、批量上传、批量导入，避免一次性打满资源。

## 实践建议

- 先定义失败语义，再选并发模型。
- 请求层统一超时、取消、重试策略。
- 关键链路加入埋点，关注耗时与失败率；相关概念可继续阅读 [Promise](https://developer.mozilla.org/zh-CN/docs/Web/JavaScript/Reference/Global_Objects/Promise) 与 [async function](https://developer.mozilla.org/zh-CN/docs/Web/JavaScript/Reference/Statements/async_function)。
