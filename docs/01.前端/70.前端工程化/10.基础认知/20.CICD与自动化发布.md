# CI CD 与自动化发布

## 阅读建议

- 不要把 CI/CD 只理解成“自动执行脚本”，它本质上是在稳定交付链路。

## 核心目标

- 理解从提交代码到上线发布，中间哪些环节适合自动化。

## 最小流水线

```text
提交代码 -> 安装依赖 -> Lint/Test -> Build -> 上传产物 -> 部署 -> 验证
```

## CI 和 CD 分别是什么

- CI 更偏持续集成，保证代码进入主干前质量可验证。
- CD 更偏持续交付/部署，让产物稳定上线。

## 前端里最常见的自动化点

- Lint 与测试
- 构建产物输出
- 产物上传 CDN / 对象存储
- 部署后健康检查

## 常见误区

- 只有 build，没有质量门禁。
- 部署成功却没有回滚预案。
- 流水线失败时没有可定位日志。
