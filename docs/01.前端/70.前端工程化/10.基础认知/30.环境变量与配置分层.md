# 环境变量与配置分层

## 阅读建议

- 这页重点不是记某个框架变量前缀，而是理解“什么配置该放哪里”。

## 核心目标

- 理解环境变量、构建配置、运行时配置的边界。

## 常见分层

| 类型       | 适合放什么                     |
| ---------- | ------------------------------ |
| 构建期变量 | API 地址、开关、构建标识       |
| 运行时配置 | 可在线切换的后端地址、灰度配置 |
| 代码常量   | 与环境无关的稳定业务常量       |

## 为什么要分层

- 因为不是所有配置都应该随着重新构建一起变化。
- 运行时可变配置和构建期固定配置混在一起，会让发布和回滚都变复杂。

## 常见误区

- 把敏感信息直接放到前端环境变量里。
- 把所有配置都塞进 `.env`，不区分运行时和构建时。
- 不做默认值和环境校验，导致线上才暴露问题。
