# 多环境发布策略

## 阅读建议

- 回答多环境问题时，优先讲“环境边界、配置隔离、上线节奏”。

## 常见环境

| 环境     | 作用                 |
| -------- | -------------------- |
| 开发环境 | 本地联调与快速迭代   |
| 测试环境 | 功能验证、联调、回归 |
| 预发环境 | 接近生产的上线前验证 |
| 生产环境 | 面向真实用户         |

## 为什么需要多环境

- 因为“能跑”不等于“能稳定上线”。
- 多环境的意义是提前暴露配置、依赖和部署链路问题。

## 多环境发布的关键点

1. 环境配置隔离
2. 构建产物可追踪
3. 发布节奏可回放
4. 问题出现时可快速回退

## 最小示例

```text
dev -> test -> pre -> prod
```

- 这是最基础的多环境发布链路，重点不在环境名字，而在每一层是否真的承担不同验证职责。

## 常见误区

- 预发环境和生产环境差异过大，导致验证失真。
- 不记录版本与环境对应关系。
- 多环境只做“名字区分”，不做真实隔离。
