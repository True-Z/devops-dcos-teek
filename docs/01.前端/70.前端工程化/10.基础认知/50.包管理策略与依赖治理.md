# 包管理策略与依赖治理

## 阅读建议

- 这页重点不是对比命令，而是理解“依赖为什么会失控，以及怎么收敛”。

## 核心目标

- 理解前端项目里为什么要区分包管理工具、锁文件、依赖边界和升级策略。

## 包管理要解决什么问题

| 问题       | 典型表现                                 |
| ---------- | ---------------------------------------- |
| 版本不一致 | 同仓库不同机器跑出不同结果               |
| 依赖膨胀   | 安装慢、体积大、漏洞多                   |
| 边界混乱   | `dependencies` 和 `devDependencies` 乱放 |
| 升级失控   | 小改动带来大面积兼容问题                 |

## 锁文件为什么重要

- 锁文件的核心价值不是“记录一下版本”，而是保证安装结果可复现。
- 没有锁文件，团队协作和 CI 环境很容易出现“我这没问题、你那不行”。

## 依赖治理主线

1. 能不加就不加
2. 能局部引就不要全量引
3. 定期清理无用依赖
4. 升级时分批做，不要一次全升

## 常见误区

- 把运行时依赖装进 `devDependencies` 或反过来。
- 长期不升级依赖，最后只能一次性大爆炸升级。
- 引入功能只用 5%，却接入超重依赖。

## 最小示例

```bash
pnpm add dayjs
pnpm add -D typescript
```
