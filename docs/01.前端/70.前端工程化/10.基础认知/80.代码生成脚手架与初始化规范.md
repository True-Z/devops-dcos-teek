# 代码生成脚手架与初始化规范

## 阅读建议

- 这页重点不是某个脚手架命令，而是理解为什么团队需要“统一起手式”。

## 核心目标

- 理解项目初始化规范、代码生成模板和脚手架为什么是工程化的一部分。

## 脚手架解决什么问题

| 问题               | 脚手架带来的价值     |
| ------------------ | -------------------- |
| 新项目起步慢       | 快速生成统一结构     |
| 团队目录风格不统一 | 固定初始化模板       |
| 配置易漏项         | 把基础配置一次性带齐 |
| 新人接手成本高     | 降低认知门槛         |

## 代码生成解决什么问题

- 当某类文件结构高度重复时，用模板生成通常比手写更稳定。
- 常见场景有：页面模板、组件模板、接口模块、测试文件、变更记录模板。

## 初始化规范通常包含什么

1. 目录结构约定
2. 包管理与锁文件约定
3. Lint / format / commit 规则
4. 环境变量模板
5. CI/CD 基础模板

## 最小示例

```text
src/
components/
pages/
composables/
tests/
```

- 重点不是目录名字本身，而是团队是否长期遵守同一套约定。

## 常见误区

- 脚手架只生成文件，不生成规范。
- 初始化模板长期不维护，最后反而误导新人。
- 代码生成过度复杂，大家宁愿绕开不用。
