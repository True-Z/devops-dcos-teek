# 微前端 模块联邦 与远程模块协作

## 阅读建议

- 这页重点不是“名词对比”，而是理解大型前端系统为什么会走到远程模块协作。

## 核心目标

- 理解微前端、模块联邦、远程模块协作分别在解决什么问题。

## 微前端是什么

- 微前端可以理解成把大型前端系统拆成多个可独立开发、独立部署、再组合运行的子系统。
- 它重点解决的是组织协作和系统边界，而不只是技术拆分。

## 模块联邦是什么

- 模块联邦更像一种运行时远程模块共享机制。
- 它让一个应用可以在运行时加载另一个应用暴露出来的模块，而不必在构建期全部打进同一个包。

## 远程模块协作怎么理解

- 远程模块协作强调的是：模块不再只来自本地构建产物，也可能来自远端应用。
- 这会带来更灵活的发布协作，但也会带来版本、依赖、故障隔离问题。

## 一张表看区别

| 概念         | 更关注什么           |
| ------------ | -------------------- |
| 微前端       | 应用级拆分与团队协作 |
| 模块联邦     | 运行时共享模块       |
| 远程模块协作 | 跨应用加载与联动     |

## 为什么会选这套方案

- 团队边界明显，需要独立发版
- 超大型系统单体前端难维护
- 希望在保持分治的同时保留一定运行时集成能力

## 最小主线

```text
主应用加载 -> 远程模块注册 -> 按需拉取远端模块 -> 运行时消费
```

## 常见难点

- 共享依赖版本不一致
- 远程模块失败时主应用如何降级
- 子应用样式与路由边界冲突
- 发布顺序和兼容窗口难管理

## 常见误区

- 还没到组织规模，就为了“先进”强上微前端。
- 只解决加载，不解决治理、监控和降级。
- 远程模块共享了太多基础依赖，最后版本爆炸。
