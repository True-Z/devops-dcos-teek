# Tailwind CSS 配置原理与响应式设计

## 阅读建议

- 这页重点不是背配置项，而是理解 Tailwind 配置文件为什么看起来绕，以及 spacing、响应式和预设到底在控制什么。

## 核心目标

- 看完后能知道 `tailwind.config` 常见配置项在做什么，`p-10` 为什么不是“10px”，以及项目里该不该改这套规则。

## 先记住 Tailwind 在做什么

- Tailwind 不是运行时解释器。
- 它更像一套“设计 token + 类名映射规则 + 构建期提取系统”。
- 你写的类名，本质是在命中它预设好的配置表。

## 配置文件里最常见的几块

| 配置项    | 作用                 | 你主要怎么理解                   |
| --------- | -------------------- | -------------------------------- |
| `content` | 扫描源码里用到的类名 | 决定哪些类最终会被生成           |
| `theme`   | 定义设计 token       | 颜色、间距、字号、断点等基础来源 |
| `extend`  | 在默认主题上追加     | 不破坏默认体系，增量扩展         |
| `plugins` | 扩展规则和能力       | 比如表单、排版、组件能力         |
| `presets` | 继承公共配置         | 多项目共享一套设计规则           |

## 为什么 `p-10` 不是 10px

- Tailwind 默认不是“数字即像素”。
- `p-10` 对应的是 spacing scale 里的第 `10` 档。
- 默认情况下：

```text
10 -> 2.5rem -> 40px（按 1rem = 16px 计算）
```

## 关键点

- `10` 不是 `10px`
- `10` 是“第 10 档 spacing token”
- 所以它更像设计系统里的一个编号，而不是原始像素值

## Tailwind 默认 spacing 怎么理解

| 类名   | 对应值    |
| ------ | --------- |
| `p-1`  | `0.25rem` |
| `p-2`  | `0.5rem`  |
| `p-4`  | `1rem`    |
| `p-8`  | `2rem`    |
| `p-10` | `2.5rem`  |

## spacing 对照速查表

| 类名   | rem       | px（按 16px 根字体） |
| ------ | --------- | -------------------- |
| `p-1`  | `0.25rem` | `4px`                |
| `p-2`  | `0.5rem`  | `8px`                |
| `p-3`  | `0.75rem` | `12px`               |
| `p-4`  | `1rem`    | `16px`               |
| `p-5`  | `1.25rem` | `20px`               |
| `p-6`  | `1.5rem`  | `24px`               |
| `p-8`  | `2rem`    | `32px`               |
| `p-10` | `2.5rem`  | `40px`               |
| `p-12` | `3rem`    | `48px`               |

- 所以在 Tailwind 里，`10` 更像 spacing token 编号，而不是“10px”。

## 如果你想“看起来更像 Uno”怎么办

### 方案一：不改默认体系

- 这是最推荐的默认方案。
- 原因：
  - 生态一致
  - 团队认知一致
  - 后续维护成本最低

### 方案二：在 `extend.spacing` 里补项目常用值

```ts
export default {
  theme: {
    extend: {
      spacing: {
        18: '4.5rem',
      },
    },
  },
}
```

- 适合：你们项目里确实缺某些常用 spacing 值
- 不适合：把整个默认体系推翻成“数字即像素”

### 方案三：完全改成数字直觉模型

- 理论上可以做
- 但不推荐
- 原因：
  - 会和 Tailwind 社区默认认知冲突
  - 后面看别人代码和示例容易错位
  - 团队协作成本会明显上升

## 我建议你怎么选

| 场景       | 更推荐的做法                                |
| ---------- | ------------------------------------------- |
| 个人项目   | 可以小范围调，但别推翻整套规则              |
| 团队项目   | 优先保留默认体系，只做增量扩展              |
| 组件库项目 | 更推荐固定 token 体系，不建议随意改数字语义 |

## 响应式在 Tailwind 里怎么设置

- Tailwind 响应式核心是 `screens`
- 常见写法本质是：

```text
sm: md: lg: xl:
```

- 它们对应不同断点宽度

## 最小示例

```html
<div class="p-4 md:p-6 lg:p-8"></div>
```

- 含义不是“随机变大”，而是：
  - 默认 `p-4`
  - 到 `md` 断点变成 `p-6`
  - 到 `lg` 断点变成 `p-8`

## 如果你要自定义断点

```ts
export default {
  theme: {
    extend: {
      screens: {
        xs: '480px',
      },
    },
  },
}
```

## 常见配置项速查表示例

| 需求         | 常见配置写法                                | 作用                 |
| ------------ | ------------------------------------------- | -------------------- |
| 配置扫描范围 | `content: ['./src/**/*.{vue,ts,tsx,html}']` | 决定哪些类会被提取   |
| 扩展 spacing | `theme.extend.spacing`                      | 补项目缺少的间距值   |
| 扩展颜色     | `theme.extend.colors`                       | 增加品牌色和业务色   |
| 扩展断点     | `theme.extend.screens`                      | 增加自定义响应式断点 |
| 保留动态类名 | `safelist: ['p-4', 'p-6']`                  | 防止构建时被裁掉     |
| 继承公共配置 | `presets: [basePreset]`                     | 多项目共享统一规则   |

## 最小配置示例

```ts
import type { Config } from 'tailwindcss'

export default {
  content: ['./src/**/*.{vue,ts,tsx,html}'],
  theme: {
    extend: {
      spacing: {
        18: '4.5rem',
      },
      colors: {
        brand: '#1f6feb',
      },
      screens: {
        xs: '480px',
      },
    },
  },
  safelist: ['p-4', 'p-6', 'xs:p-4'],
} satisfies Config
```

## 怎么理解这段配置

- `content`：告诉 Tailwind 去哪些源码里找类名。
- `spacing`：给项目补自定义间距 token。
- `colors`：把品牌色纳入统一 token。
- `screens`：增加自定义响应式断点。
- `safelist`：让构建期保留某些无法静态识别的类名。

## `@nsdk/web-ele` 这类项目该怎么理解

- 如果项目已经在用 Tailwind
- 默认建议：
  - 不要强行改成“Uno 那种数字直觉模型”
  - 优先顺着预设系统使用
  - 只有确实不够用时，再通过 `extend` 或 `preset` 小范围补充

## 最终判断

| 问题                                              | 更推荐的答案                  |
| ------------------------------------------------- | ----------------------------- |
| 要不要把 Tailwind 改成 `p-10 = 10px` 这种直觉模型 | 不推荐                        |
| 项目里要不要接受预设系统限制                      | 推荐，除非有明确设计系统理由  |
| 真有缺口怎么办                                    | 用 `extend` / `preset` 增量补 |

## 常见误区

- 把 Tailwind 当“数字即像素”的系统来理解。
- 一上来就想推翻默认 spacing 体系。
- 不先理解 token 语义，就去硬改配置。
