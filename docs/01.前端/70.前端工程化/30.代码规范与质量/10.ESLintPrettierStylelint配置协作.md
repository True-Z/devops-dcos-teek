# ESLint Prettier Stylelint 配置协作

## 阅读建议

- 这页重点不是罗列插件，而是分清每个工具的职责边界。

## 三者分别负责什么

| 工具      | 主要职责                             |
| --------- | ------------------------------------ |
| ESLint    | 代码质量、潜在错误、风格规则的一部分 |
| Prettier  | 代码格式化                           |
| Stylelint | CSS / SCSS / 样式代码规范            |

## 为什么要协作而不是混用职责

- Prettier 擅长格式统一，不擅长做复杂语义规则。
- ESLint 擅长代码规则，但不适合承担所有格式化职责。
- Stylelint 负责样式侧规则，避免把 CSS 全塞进 ESLint 体系。

## 常见插件与适配

| 工具      | 常见插件/适配                                                      |
| --------- | ------------------------------------------------------------------ |
| ESLint    | `typescript-eslint`、`eslint-plugin-vue`、`eslint-config-prettier` |
| Prettier  | `prettier-plugin-tailwindcss`                                      |
| Stylelint | `stylelint-config-standard`、`stylelint-config-recess-order`       |

## 最小示例

```js
// eslint.config.js
import js from '@eslint/js'
import vue from 'eslint-plugin-vue'
import eslintConfigPrettier from 'eslint-config-prettier'

export default [js.configs.recommended, ...vue.configs['flat/recommended'], eslintConfigPrettier]
```

## 配置建议

- ESLint 负责“代码是否合理”。
- Prettier 负责“代码长什么样”。
- Stylelint 负责“样式是否规范”。
- 提交前最好配合 `lint-staged` 或 CI 保底。
