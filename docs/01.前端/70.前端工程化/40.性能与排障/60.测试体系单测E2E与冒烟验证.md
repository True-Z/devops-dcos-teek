# 测试体系 单测 E2E 与冒烟验证

## 阅读建议

- 这页重点不是背测试名词，而是理解不同测试层级各自拦截什么风险。

## 核心目标

- 理解为什么前端测试体系不该只有一种测试方式。

## 常见测试层级

| 类型     | 更适合发现什么问题             |
| -------- | ------------------------------ |
| 单元测试 | 纯逻辑、函数、组件局部行为     |
| 集成测试 | 页面模块协作、状态与交互链路   |
| E2E      | 接近真实用户路径的端到端问题   |
| 冒烟验证 | 发布后最关键主链路是否还能跑通 |

## 单测在前端里更适合什么

- 工具函数
- 状态转换逻辑
- 组件条件渲染
- 表单校验与边界分支

## E2E 为什么必要

- 因为很多问题不是单个函数错，而是页面、路由、接口、构建产物一起协作时才暴露。
- E2E 更适合覆盖登录、下单、提交、搜索等关键链路。

## 冒烟验证怎么理解

- 冒烟验证不是完整回归，而是上线前后快速确认核心路径没挂。
- 它通常只覆盖最关键的少数链路，比如首页能打开、登录能成功、核心功能能点击。

## 推荐主线

1. 单测兜底纯逻辑和稳定函数。
2. 集成测试覆盖局部模块协作。
3. E2E 覆盖关键用户路径。
4. 冒烟验证用于发布前后快速止损。

## 最小示例

```text
单测保逻辑
E2E保主链路
冒烟保上线安全
```

## 常见误区

- 只有单测，没有真实页面链路验证。
- E2E 覆盖太多细节，维护成本爆炸。
- 冒烟验证没有固定清单，全靠人工印象。
