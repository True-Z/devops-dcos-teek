# 懒加载治理

## 阅读建议

- 这页重点不是把所有资源都延后，而是让懒加载真正服务关键路径，而不是制造更多白屏和等待。

## 核心目标

- 理解懒加载治理的关键不是“有没有懒加载”，而是“懒加载边界、时机、回退和监控是否合理”。

## 常见懒加载对象

| 对象       | 常见做法                   |
| ---------- | -------------------------- |
| 路由页面   | 动态导入、按页面拆包       |
| 大型组件   | 异步组件、交互触发后再加载 |
| 图片       | 进入视口前后加载           |
| 第三方脚本 | 用户触发或空闲时再加载     |
| 非关键数据 | 首屏后补拉或按可见区域触发 |

## 为什么要加“治理”两个字

- 因为懒加载一旦缺少规范，常见结果不是更快，而是首屏白块更多、错误恢复更差、调试更困难。
- 真正的治理要同时覆盖触发条件、占位方案、失败兜底和效果评估。

## 推荐治理主线

1. 先识别关键路径，不把关键资源误懒加载。
2. 为懒加载对象设计占位、重试和失败提示。
3. 用监控验证是否真的缩短了首屏与交互耗时。
4. 定期清理已经没有收益的懒加载拆分点。

## 最小示例

```ts
const UserChart = defineAsyncComponent(() => import('./UserChart.vue'))
```

- 异步组件只是起点，真正需要补的是加载态、失败态和触发时机设计。

## 常见治理维度

| 维度   | 重点问题                       |
| ------ | ------------------------------ |
| 边界   | 哪些资源必须首屏，哪些可以延后 |
| 体验   | 是否有 skeleton、loading、空态 |
| 稳定性 | 失败后能否重试，是否可降级     |
| 监控   | 是否跟踪首屏、交互、错误率变化 |

## 常见误区

- 首屏主视图也做懒加载，结果用户看到空页面。
- 只做动态导入，不做 fallback 和失败恢复。
- 懒加载拆分越来越碎，却没有回看真实收益。
