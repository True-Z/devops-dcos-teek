# 首屏指标 LCP INP CLS 治理

## 阅读建议

- 这页重点不是死记指标定义，而是把指标和真实页面问题对应起来理解。

## 核心目标

- 理解 LCP、INP、CLS 分别反映“看见得快不快、操作跟手不跟手、页面稳不稳定”。

## 一张表看三类指标

| 指标 | 更关注什么           | 常见问题来源                   |
| ---- | -------------------- | ------------------------------ |
| LCP  | 首屏主要内容出现速度 | 主图、CSS、主包过重            |
| INP  | 用户交互响应延迟     | 长任务、重计算、事件拥堵       |
| CLS  | 页面视觉稳定性       | 图片无尺寸、字体切换、异步插入 |

## 治理主线

1. 先识别主要掉分指标。
2. 按资源、执行、布局三个方向拆解来源。
3. 为关键页面建立指标采集和回归阈值。
4. 把指标治理和发布门禁、监控看板联动起来。

## 最小示例

```text
LCP 看首屏主资源
INP 看交互长任务
CLS 看布局抖动来源
```

## 常见治理方向

| 指标 | 常见优化方向                           |
| ---- | -------------------------------------- |
| LCP  | 优化主图、关键 CSS、首屏包体积         |
| INP  | 拆长任务、延后非关键脚本、减少同步计算 |
| CLS  | 预留尺寸、稳定字体、减少异步插入       |

## 常见误区

- 只看 Lighthouse 分数，不看线上真实用户数据。
- 所有页面统一治理，不区分关键页面和高流量页面。
- 指标下降后只做一次性修复，没有持续追踪。
