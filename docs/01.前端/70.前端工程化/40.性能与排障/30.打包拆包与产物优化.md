# 打包拆包与产物优化

## 阅读建议

- 不要只盯 bundle 体积，要一起看加载顺序、缓存命中和执行成本。

## 核心目标

- 理解为什么要拆包，以及拆包后如何真正提升页面性能。

## 常见拆包方向

| 方向           | 目标                   |
| -------------- | ---------------------- |
| 路由级拆包     | 减少首屏主包           |
| 第三方依赖拆包 | 提升缓存复用           |
| 大组件按需加载 | 避免低频页面拖慢主链路 |

## 拆包不等于一定更快

- 包拆得太碎，请求和调度成本也会增加。
- 所以重点不是“越碎越好”，而是“关键路径更短”。

## 优化主线

1. 先确认主包是否过大
2. 再识别重依赖与低频功能
3. 最后决定按路由、按依赖还是按场景拆分
