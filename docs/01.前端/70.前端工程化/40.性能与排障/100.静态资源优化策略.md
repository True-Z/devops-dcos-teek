# 静态资源优化策略

## 阅读建议

- 这页重点不是单独看某一种资源，而是把 JS、CSS、图片、字体、第三方脚本放到同一条资源治理链路里理解。

## 核心目标

- 理解静态资源优化不是只做压缩，而是同时管理体积、加载顺序、缓存命中、执行成本和可回收性。

## 常见资源类型

| 资源类型   | 重点关注什么                   |
| ---------- | ------------------------------ |
| JS         | 拆包、执行成本、缓存复用       |
| CSS        | 关键样式、体积、阻塞渲染       |
| 图片       | 格式、尺寸、懒加载、占位       |
| 字体       | 子集化、回退、加载时机         |
| 第三方脚本 | 体积、阻塞、失败降级、可观测性 |

## 治理主线

1. 先识别首屏关键资源和非关键资源。
2. 对关键资源做优先级控制和缓存策略设计。
3. 对非关键资源做延迟加载、异步加载或按需加载。
4. 建立版本、回收和监控闭环，避免资源长期膨胀。

## 工程化层面的重点

- 资源文件名尽量带内容指纹，提升长缓存命中率。
- HTML 入口与静态资源走不同缓存策略。
- 资源引用链要可追踪，避免线上出现孤儿资源和失效版本。
- 第三方脚本要有兜底和降级，不要直接堵在主链路上。

## 最小示例

```text
首屏关键资源优先 -> 非关键资源延后 -> 带 hash 资源长缓存 -> 旧版本按窗口回收
```

## 常见误区

- 只盯压缩率，不看加载顺序和主线程执行时间。
- 把所有资源都放进首屏，导致关键路径过长。
- 资源上 CDN 了就以为结束，没有版本回收和回滚预案。
