# 发布回滚与稳定性保障

## 阅读建议

- 发布不是“构建成功就结束”，重点是出问题后能不能快速止损。

## 核心目标

- 理解发布前、发布中、发布后各自该有什么兜底手段。

## 常见保障手段

| 阶段   | 保障措施                         |
| ------ | -------------------------------- |
| 发布前 | 灰度、检查清单、回滚预案         |
| 发布中 | 版本指纹、健康检查、监控埋点     |
| 发布后 | 错误告警、回滚开关、快速回退产物 |

## 前端回滚为什么常见

- 静态资源一旦发布错误，用户会直接感知白屏、报错、样式错乱。
- 所以前端上线必须考虑“旧资源兼容”和“新资源失败时怎么回退”。

## 最小思路

1. 每次产物都带版本指纹
2. 保留最近稳定版本
3. 出问题时优先恢复入口 HTML 与静态资源引用

## 常见误区

- 只回滚代码仓库，不回滚实际静态资源产物。
- 发布没有版本记录，问题出现后找不到可回退目标。
