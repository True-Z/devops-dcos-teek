# 日志规范 埋点模型 与看板口径一致性

## 阅读建议

- 这页重点不是“埋得越多越好”，而是让日志、事件、看板指标说的是同一件事。

## 核心目标

- 理解为什么埋点混乱、日志字段不统一、指标口径不一致，会让监控和业务分析失真。

## 三类数据的边界

| 类型     | 更适合记录什么                 |
| -------- | ------------------------------ |
| 日志     | 运行过程、错误上下文、诊断信息 |
| 埋点     | 用户行为、关键流程节点         |
| 指标看板 | 聚合后的业务或稳定性结果       |

## 为什么要统一口径

- 同一个“转化率”如果前端、后端、BI 看板的定义不一致，最后结论就会冲突。
- 所以真正要统一的不是图表样式，而是事件定义、字段语义和统计边界。

## 埋点模型建议

1. 明确事件名规范
2. 统一公共字段，如页面、用户、版本、环境、时间
3. 区分曝光、点击、提交、成功、失败这些事件语义
4. 避免一个事件承载过多含义

## 最小示例

```json
{
  "event": "order_submit_success",
  "page": "checkout",
  "version": "1.2.3",
  "env": "prod"
}
```

## 看板口径一致性怎么做

- 关键指标要有统一定义文档。
- 事件采集方、看板消费方、业务解释方要用同一份口径。
- 改事件或改字段前要考虑历史兼容和看板影响。

## 常见误区

- 事件名随手写，过段时间没人知道含义。
- 同一个成功动作，埋点触发了两次，导致转化虚高。
- 只搭看板，不维护口径说明。
