# 监控埋点与前端告警

## 阅读建议

- 不要把监控只理解成“报错上报”，它还包括性能、行为和稳定性信号。

## 核心目标

- 理解前端线上问题为什么必须靠监控闭环发现，而不能只靠用户反馈。

## 常见监控维度

| 维度       | 常见指标                                  |
| ---------- | ----------------------------------------- |
| 错误监控   | JS Error、Promise Rejection、资源加载失败 |
| 性能监控   | FCP、LCP、CLS、TTFB、长任务               |
| 行为埋点   | 页面访问、按钮点击、关键转化              |
| 稳定性监控 | 白屏率、接口失败率、发布后异常波动        |

## 最小错误上报示例

```js
window.addEventListener('error', (event) => {
  reportError({
    message: event.message,
    filename: event.filename,
  })
})
```

## 为什么要做告警

- 监控只是收集数据，告警才是让问题进入处理流程。
- 没有阈值、分级和通知机制，监控数据很容易变成“看不完的日志”。

## 常见误区

- 只上报错误，不上报版本号和环境信息。
- 只做埋点，不做异常聚合与告警分级。
- 告警过多导致团队麻木。
