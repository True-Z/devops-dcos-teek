# 关键渲染路径与资源优先级

## 阅读建议

- 这页重点不是罗列浏览器机制，而是理解哪些资源真的在首屏关键链路上，哪些不该去抢带宽和主线程。

## 核心目标

- 理解性能优化要先缩短关键渲染路径，而不是让所有资源都“尽快加载”。

## 什么是关键渲染路径

- 可以粗略理解成：从用户打开页面，到首屏关键内容真正可见，这条链路上必须经历的资源下载、解析、执行和渲染过程。

## 常见资源优先级划分

| 类型         | 更适合什么策略             |
| ------------ | -------------------------- |
| HTML 入口    | 快速返回，避免长缓存       |
| 首屏关键 CSS | 优先加载，减少阻塞         |
| 首屏主包 JS  | 控制体积，避免同步执行过重 |
| 首屏主图     | 识别 LCP 资源并优先处理    |
| 非关键脚本   | 延后、异步、空闲时再加载   |

## 推荐治理主线

1. 标出首屏必须资源。
2. 把非关键资源从首屏链路中移开。
3. 减少阻塞渲染的 CSS 和同步脚本。
4. 持续用监控验证优先级调整是否有效。

## 最小示例

```text
用户请求 -> HTML -> 关键 CSS / 首屏主图 / 最小主包 -> 首屏可见 -> 非关键资源补加载
```

## 常见误区

- 所有资源都想提前加载，结果真正关键资源反而被挤占。
- 只看下载大小，不看脚本执行和样式阻塞。
- 首屏首要内容都不明确，就开始泛化优化。
