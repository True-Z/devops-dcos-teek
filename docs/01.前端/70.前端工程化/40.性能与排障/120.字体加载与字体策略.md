# 字体加载与字体策略

## 阅读建议

- 这页重点不是只会写 `@font-face`，而是理解品牌字体、系统回退和加载性能之间怎么平衡。

## 核心目标

- 理解字体策略既影响品牌一致性，也直接影响首屏渲染、文本稳定性和跨平台体验。

## 字体策略常见选项

| 方案         | 更适合什么场景                 |
| ------------ | ------------------------------ |
| 系统字体栈   | 后台系统、性能优先页面         |
| 自托管字体   | 品牌站点、可控缓存与版本管理   |
| 第三方字体源 | 快速接入，但要评估可用性与时延 |
| 子集字体     | 文字集可控、需要降低体积的场景 |

## 字体优化主线

1. 优先评估是否真的需要自定义字体。
2. 需要时优先使用 `woff2`，并尽量做子集化。
3. 为关键字重或关键页面控制预加载范围。
4. 配置回退字体和 `font-display`，减少文本长时间不可见。

## 最小示例

```css
@font-face {
  font-family: 'Brand Sans';
  src: url('/fonts/brand-sans.woff2') format('woff2');
  font-display: swap;
}
```

- `font-display: swap` 的核心价值，是先让文字可见，再等待品牌字体替换。

## 实施重点

- 中英文混排时要单独评估字库体积，不要低估中文字体成本。
- 不同字重应按真实使用情况加载，避免一次性全量下发。
- 品牌字体上线前要验证 CLS、FOUT/FOIT 和缓存策略。

## 常见误区

- 字体文件很大，却没有子集化和缓存策略。
- 每个字重都预加载，导致首屏资源拥塞。
- 只看视觉稿，不看低端设备和弱网下的文本可见性。
