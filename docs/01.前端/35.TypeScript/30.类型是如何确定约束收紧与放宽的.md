# TypeScript 类型是如何确定约束收紧与放宽的

## 阅读建议

- 这页重点不是只会写 `extends` 或 `as const`，而是理解 TypeScript 为什么会把一个值推成当前这个类型。

## 核心目标

- 看完后能从“类型确定、约束、收紧、放宽”四个角度解释 TypeScript 的推断行为。

## 类型是怎么确定的

| 方式       | 说明                               |
| ---------- | ---------------------------------- |
| 显式标注   | 你直接告诉 TS 它是什么类型         |
| 字面量推断 | TS 根据初始值先给一个类型          |
| 上下文推断 | 根据函数参数、返回值、赋值位置推断 |
| 泛型推断   | 根据传入值反推出泛型参数           |

## 类型是怎么被约束的

| 方式         | 说明                        |
| ------------ | --------------------------- |
| `extends`    | 要求类型满足某个边界        |
| `keyof`      | 限制 key 只能来自对象已有键 |
| 泛型参数约束 | 让未知类型不是完全无边界    |

## 类型怎么收紧

| 方式       | 说明                                 |
| ---------- | ------------------------------------ |
| 字面量类型 | `'ok'` 比 `string` 更具体            |
| `as const` | 把值和属性尽量收成最窄               |
| 类型守卫   | `typeof` / `in` / 自定义守卫缩小范围 |
| 控制流分析 | `if` 分支里类型会被进一步缩小        |

## 类型怎么放宽

| 方式              | 说明                          |
| ----------------- | ----------------------------- |
| 宽化              | `'abc'` 最后可能变成 `string` |
| 联合扩大          | 类型边界变得更宽              |
| `any` / `unknown` | 进入更宽或更不确定的区域      |

## 最小示例

```ts
const status = 'ok' // 先是字面量倾向
let text = 'hello' // 更容易宽化成 string

function getValue<T extends { id: number }>(value: T) {
  return value.id
}
```

## 原理感怎么理解

- TypeScript 不是“随便猜类型”。
- 它是在当前上下文里，尽量找一个既不太窄、也不太宽的类型。
- 约束是在告诉它“至少要满足什么”。
- 收窄是在运行路径上告诉它“现在更具体了”。
- 放宽是在避免类型太死，留出更一般的可用范围。

## 常见误区

- 以为 TS 的推断是黑盒魔法。
- 只会写语法，不知道当前类型为什么变宽或变窄。
- 把“约束”和“推断结果”当成一回事。
