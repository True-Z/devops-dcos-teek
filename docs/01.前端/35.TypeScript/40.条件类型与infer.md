# TypeScript 条件类型与 infer

## 阅读建议

- 这页重点不是记语法，而是理解 TypeScript 怎么在类型层做“判断”和“拆解”。

## 核心目标

- 看完后能知道条件类型是在做什么，`infer` 又是怎样把某个类型片段“提取出来”的。

## 条件类型是什么

- 条件类型可以理解成“类型层 if”。
- 它根据一个类型是否满足另一个类型条件，决定返回哪一支结果。

## 最小示例

```ts
type IsString<T> = T extends string ? true : false
```

- 这里的意思是：如果 `T` 能赋值给 `string`，结果就是 `true`，否则就是 `false`。

## `infer` 是什么

- `infer` 可以理解成“在条件类型里声明一个待提取的类型变量”。
- 它不是随便出现的，只能放在条件类型判断里。

## 最小示例

```ts
type GetReturnType<T> = T extends (...args: any[]) => infer R ? R : never
```

- 这里的意思是：如果 `T` 是函数类型，就把返回值类型提出来记成 `R`。

## 条件类型和 infer 怎么配合

| 能力     | 作用                           |
| -------- | ------------------------------ |
| 条件类型 | 做判断                         |
| `infer`  | 从满足条件的类型里提取某一部分 |

## 常见场景

| 场景              | 写法思路                                     |
| ----------------- | -------------------------------------------- |
| 提取函数返回值    | `T extends (...args) => infer R ? R : never` |
| 提取 Promise 结果 | `T extends Promise<infer R> ? R : T`         |
| 提取数组元素类型  | `T extends Array<infer U> ? U : never`       |

## 为什么它重要

- 很多 TypeScript 工具类型，本质都依赖这套“先判断、再提取”的能力。
- 没有条件类型和 `infer`，很多复杂类型推导根本没法表达。

## 常见误区

- 只会抄 `infer`，不知道它是在“提取类型片段”。
- 把条件类型当普通运行时代码理解。
- 一开始就写很复杂的嵌套，反而看不清本质。
