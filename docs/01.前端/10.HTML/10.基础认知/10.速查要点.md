# HTML 速查要点

## 核心定位

- HTML 负责定义内容结构与语义，不负责样式和业务逻辑。
- 页面可维护性的基础是“结构先行”，语义标签优先于无语义容器；涉及深入实践可继续看 [HTML 语义化与可访问性](/fe/html-semantic-a11y) 与 [HTML 表单与校验要点](/fe/html-form-validation)。

## 语义化速记

| 场景       | 推荐标签            | 价值                     |
| ---------- | ------------------- | ------------------------ |
| 页面头尾   | `header` / `footer` | 提升结构可读性与可访问性 |
| 主内容     | `main`              | 明确页面主体区域         |
| 导航       | `nav`               | 便于辅助技术识别导航块   |
| 独立内容块 | `article`           | 适合文章、卡片、帖子     |
| 分区内容   | `section`           | 有明确主题的小节         |
| 补充内容   | `aside`             | 侧栏、推荐、广告等       |

## 表单要点

- `label` 与表单控件关联是基础要求，可提升可点击区域与可访问性。
- 原生校验（`required`、`type`、`pattern`）优先于全量自定义校验。
- 输入建议通过 `autocomplete` 提升体验。

## 可访问性（a11y）最低基线

- 图片需有 `alt`；纯装饰图可用空 `alt`。
- 交互元素应使用语义元素（优先 `button`，避免 div 冒充按钮）。
- 键盘可达性必须可用（Tab 顺序、焦点可见）。

## 最小示例

```html
<main>
  <article>
    <h1>文章标题</h1>
    <p>正文内容</p>
    <button type="button">提交</button>
  </article>
</main>
```

- 这个示例体现了 HTML 的三个核心点：结构语义、标题层级、原生交互元素。

## 常见误区

- 用大量 `div` 替代语义标签，导致结构不清晰。
- 只追求视觉效果，忽略可访问性与 SEO 基础。
- 表单仅做前端校验，不做后端校验兜底。

## 实施建议

- 页面开发先画“语义结构草图”，再写样式。
- 关键模板建立结构规范（头部、主体、导航、表单区）。
- 新页面至少自检一次：语义、可访问性、表单可用性。
