# Vue 响应式原理

## 阅读建议

- 这页重点不是背 API，而是理解“数据变了，Vue 为什么知道要更新”。

## 核心目标

- 理解依赖收集、触发更新、调度执行这三步主线。

## 最小主线

```text
读取数据 -> 收集依赖
修改数据 -> 触发依赖
调度更新 -> 组件重新渲染
```

## Vue2 和 Vue3 的核心差异

| 版本 | 核心实现                | 特点                         |
| ---- | ----------------------- | ---------------------------- |
| Vue2 | `Object.defineProperty` | 对新增属性、数组索引拦截有限 |
| Vue3 | `Proxy`                 | 拦截更完整，能力边界更自然   |

## Vue3 里发生了什么

- `reactive()` 会返回一个代理对象。
- 当模板或副作用函数读取属性时，会触发依赖收集。
- 当属性被修改时，会触发对应依赖重新执行。

## 为什么需要调度

- Vue 不会每改一次数据就立刻同步重新渲染整棵子树。
- 它通常会把同一轮更新合并调度，减少重复渲染成本。

## 常见追问

- 为什么 `ref` 有 `.value`：因为它要把单值包装成可跟踪对象。
- 为什么解构后可能失去响应式：因为你拿到的可能已经不是代理读取路径。
- 为什么不要把所有对象都随意深层嵌套响应式：维护和更新边界会变差。
