## `ref` 和 `reactive` 有什么区别

- `ref` 更适合单值或需要显式 `.value` 的场景。
- `reactive` 更适合对象结构。

## `watch` 和 `watchEffect` 有什么区别

- `watch` 更适合明确指定依赖源，并且需要拿到新旧值的场景。
- `watchEffect` 更适合“执行过程中自动收集依赖”的副作用逻辑。

```ts
watch(
  () => form.id,
  (newValue, oldValue) => {
    console.log(newValue, oldValue)
  },
)
```

```ts
watchEffect(() => {
  console.log(route.params.id)
})
```

- 面试里最稳的回答是：`watch` 偏精确控制，`watchEffect` 偏自动依赖收集。

## `computed` 和 `watch` 有什么区别

- `computed` 用来产生派生值，强调“基于依赖缓存结果”。
- `watch` 用来响应变化后执行副作用，强调“变化发生后做事”。

## 为什么 `key` 很重要

- `key` 帮助 Vue 更准确地识别节点身份。
- 列表更新时没有稳定 `key`，更容易出现复用错误和额外 patch。

## `diff` 和 `key` 常怎么问

- 通常不会追问完整源码，而是问：为什么列表必须给稳定 `key`。
- `key` 的价值在于帮助 Vue 在 patch 阶段更稳定地判断“哪个节点是同一个节点”。
- 如果 `key` 不稳定，可能导致错误复用、额外移动，甚至状态错位。

## 生命周期怎么答

- 不要背顺序表，要按“创建 -> 挂载 -> 更新 -> 卸载”主线去讲。

## 常见追问

- 为什么 `watchEffect` 不适合无脑写大量异步副作用。
- 为什么列表里不要用随机值做 `key`。
