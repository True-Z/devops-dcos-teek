# Vue 状态持久化 缓存恢复 与页面返回态管理

## 阅读建议

- 这页重点不是单独讲缓存，而是把“刷新后还能不能恢复”“返回列表还能不能保留上下文”放到一条主线里看。

## 核心目标

- 理解哪些状态该持久化，哪些状态只该短期缓存。
- 理解页面返回态为什么常常比单纯状态存储更影响体验。

## 常见状态分层

| 类型               | 更适合放哪里         |
| ------------------ | -------------------- |
| 登录态、用户偏好   | 持久化存储           |
| 页面筛选条件       | 页面级缓存或路由参数 |
| 临时 UI 状态       | 组件本地状态         |
| 跨页面共享业务状态 | Pinia 或页面缓存层   |

## 什么叫页面返回态

- 页面返回态指用户离开一个页面后再回来，希望看到的是“上次离开时的上下文”，而不是完全重置。
- 最常见场景：
  - 列表页筛选条件
  - 滚动位置
  - Tab 选中状态
  - 表单草稿

## 常见实现思路

| 方案               | 适合场景               | 风险             |
| ------------------ | ---------------------- | ---------------- |
| 路由参数 / query   | 筛选、分页、排序       | URL 可能变长     |
| `sessionStorage`   | 单会话内恢复           | 切设备不可恢复   |
| `localStorage`     | 偏好设置、长期状态     | 容易过期和污染   |
| Pinia + 持久化插件 | 跨页面共享状态         | 需要控制边界     |
| `KeepAlive`        | 页面切换返回保留上下文 | 缓存过多会占内存 |

## 最小示例

```ts
watch(
  () => filters.value,
  (value) => {
    sessionStorage.setItem('user-list-filters', JSON.stringify(value))
  },
  { deep: true },
)
```

## 推荐主线

1. 先判断状态是不是用户真的期待恢复。
2. 如果只是页面返回上下文，优先考虑轻量缓存或路由参数。
3. 如果是跨页面长期共享，再考虑全局状态持久化。
4. 不要为了“能恢复”把所有状态都存下来。

## 为什么 `KeepAlive` 常被一起问

- 因为它也能保留页面返回时的上下文。
- 但它解决的是组件实例缓存，不等于通用持久化策略。
- 如果页面一刷新就没了，那说明你需要的是持久化，而不只是实例缓存。

## 常见误区

- 所有页面都开持久化，最后状态污染很严重。
- 只保留筛选条件，不保留滚动位置，返回体验仍然断裂。
- 把 `KeepAlive` 当成长期数据恢复方案。
