# Vue 受控组件与非受控组件策略

## 阅读建议

- 这页重点不是背术语，而是判断组件状态应该由父层统一控制，还是由组件内部自行维护。

## 核心目标

- 理解受控与非受控的本质，是状态归属和变更责任的划分问题。

## 一张表看区别

| 模式       | 核心特征                         | 更适合什么场景               |
| ---------- | -------------------------------- | ---------------------------- |
| 受控组件   | 状态由父层传入，变更通过事件上抛 | 表单联动、筛选同步、状态追踪 |
| 非受控组件 | 状态主要保存在组件内部           | 简单输入、局部交互、临时状态 |

## 什么时候更适合受控

- 父组件需要统一管理多个字段或多个子组件状态时。
- 组件状态要和路由、表单、store 或接口请求联动时。
- 需要可追踪、可回放、可重置的状态流时。

## 什么时候可以非受控

- 状态只在组件内部短暂存在，不影响外部业务流时。
- 组件只是局部增强交互，比如展开、聚焦、临时搜索词时。
- 调用方不需要监听每一次细粒度变更时。

## 推荐设计主线

1. 业务关键状态优先受控。
2. 纯局部临时状态可以非受控。
3. 同一个组件尽量明确主导模式，避免边界混乱。
4. 如需兼容两种模式，先定义好单一状态源和优先级。

## 最小示例

```vue
<BaseInput :model-value="keyword" @update:model-value="keyword = $event" />
```

- 这是典型受控写法，输入值由父层持有，组件只负责展示和派发更新。

## 兼容双模式时要注意什么

| 关注点     | 说明                                      |
| ---------- | ----------------------------------------- |
| 单一数据源 | 不要同时让内部状态和外部状态互相抢        |
| 默认值语义 | `defaultValue` 和 `modelValue` 边界要清楚 |
| 事件语义   | 更新事件命名要稳定且可预测                |
| 文档说明   | 明确调用方何时该用哪种模式                |

## 常见误区

- 明明需要联动校验，却把关键状态藏在组件内部。
- 父组件传了值，子组件内部又维护一份镜像状态，最后不同步。
- 为了“更灵活”同时暴露太多状态入口，导致调用方无所适从。
