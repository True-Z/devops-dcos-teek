# Vue 权限控制 路由守卫 与页面错误状态

## 阅读建议

- 这页重点不是只记守卫 API，而是理解“权限校验、页面进入条件、错误状态兜底”怎么协同。

## 核心目标

- 理解 Vue 应用里权限控制为什么不能只靠按钮显隐。

## 权限控制常见分层

| 层级   | 更适合做什么                   |
| ------ | ------------------------------ |
| 路由层 | 控制页面能不能进入             |
| 页面层 | 控制页面状态与空态、无权态     |
| 组件层 | 控制局部按钮、操作区、字段展示 |

## 为什么路由守卫重要

- 路由守卫更适合做“进入页面前”的前置判断。
- 它可以把未登录、无权限、环境不满足等情况提前拦住。

```ts
router.beforeEach((to) => {
  if (to.meta.requiresAuth && !userStore.isLogin) {
    return '/login'
  }
})
```

## 但为什么不能只靠守卫

- 因为同一个页面内部仍然可能有更细粒度权限差异。
- 比如页面可以进，但某些按钮、表格列、操作入口不应该展示。

## 页面级错误状态怎么组织

- 页面级错误状态通常包括：
  - 加载中
  - 空数据
  - 无权限
  - 请求失败
  - 部分区域失败但页面主体仍可用

## 推荐主线

1. 路由层先做“能不能进”。
2. 页面层再做“进来之后当前是什么状态”。
3. 组件层最后做“当前用户能看到和操作哪些局部能力”。

## 最小示例

```vue
<template>
  <NoPermission v-if="state === 'forbidden'" />
  <ErrorState v-else-if="state === 'error'" />
  <PageContent v-else />
</template>
```

- 这样页面状态比“报错就整页崩掉”更可控。

## 常见误区

- 只做按钮显隐，不做真实路由和接口校验。
- 所有失败都跳同一个错误页，导致用户无法判断发生了什么。
- 权限状态和业务状态混在一起，页面逻辑越来越乱。
