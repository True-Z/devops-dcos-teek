# Vue 列表页 详情页 编辑页 状态协作模式

## 阅读建议

- 这页重点不是单页内部怎么写，而是列表、详情、编辑三类页面如何共享上下文，又避免状态互相污染。

## 核心目标

- 理解列表页、详情页、编辑页在真实业务里为什么经常要联动设计状态。

## 最常见的页面链路

```text
列表页 -> 进入详情页 -> 进入编辑页 -> 保存成功 -> 返回详情或列表
```

- 这条链路里最容易出问题的不是跳转本身，而是返回后状态是否还能保持用户原有上下文。

## 三类页面关注点

| 页面类型 | 最常保留什么                     |
| -------- | -------------------------------- |
| 列表页   | 筛选条件、分页、滚动位置、选中态 |
| 详情页   | 当前实体数据、所属列表上下文     |
| 编辑页   | 草稿、校验状态、提交结果         |

## 推荐协作主线

1. 列表页负责保留筛选和浏览上下文。
2. 详情页负责承接实体展示，不要重复持有过多列表状态。
3. 编辑页负责草稿和提交流程，不直接改写列表页临时状态。
4. 保存成功后，通过明确刷新策略决定谁需要重新拉取数据。

## 常见状态设计方式

| 方案             | 更适合场景                           |
| ---------------- | ------------------------------------ |
| 路由参数 / query | 保留筛选、分页、Tab                  |
| 页面缓存         | 返回列表时保留滚动位置和上下文       |
| Pinia            | 跨页面共享当前实体、草稿或全局上下文 |
| 局部表单状态     | 编辑页内部交互与校验                 |

## 最小示例

```ts
router.push({
  path: `/user/${id}`,
  query: {
    page: String(filters.page),
    keyword: filters.keyword,
  },
})
```

- 这样详情页返回列表时，更容易恢复原来的筛选上下文。

## 保存成功后的常见策略

| 场景               | 更推荐的处理方式                   |
| ------------------ | ---------------------------------- |
| 详情页字段有变化   | 回详情页并刷新当前实体             |
| 列表摘要字段有变化 | 返回列表并局部刷新当前项或重新请求 |
| 编辑失败           | 保留草稿和错误信息                 |

## 常见误区

- 列表、详情、编辑三页各存一份同样的数据，最后状态互相打架。
- 返回列表时只恢复分页，不恢复筛选和滚动位置。
- 保存成功后无脑全局刷新，用户上下文全部丢失。
