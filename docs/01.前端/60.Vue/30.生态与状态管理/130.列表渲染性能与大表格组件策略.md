# Vue 列表渲染性能与大表格组件策略

## 阅读建议

- 这页重点不是只谈虚拟列表，而是把数据量、渲染量、交互量和组件抽象方式一起看。

## 核心目标

- 理解大列表和大表格性能问题，往往不只是“数据太多”，而是渲染策略、状态粒度和组件层级一起失控。

## 性能瓶颈通常来自哪里

| 方向     | 常见问题                         |
| -------- | -------------------------------- |
| 数据量   | 一次性加载和渲染过多             |
| 渲染层级 | 行、列、单元格组件过深           |
| 状态粒度 | 一个状态变化触发整表重渲染       |
| 交互能力 | 固定列、合并单元格、编辑态成本高 |

## 推荐治理主线

1. 先确认问题出在数据获取、渲染还是交互。
2. 控制首屏渲染量，不一次性铺满所有行。
3. 让行级、单元格级更新尽量局部化。
4. 超大数据量场景再引入虚拟滚动或分页策略。

## 通用表格组件怎么设计

| 关注点   | 更推荐的做法                     |
| -------- | -------------------------------- |
| 列配置   | 稳定描述字段、宽度、对齐、渲染位 |
| 扩展位   | 操作列、空态、头部工具栏走 slots |
| 状态管理 | 排序、筛选、选中态边界清晰       |
| 性能     | 避免整表级响应式对象过大         |

## 最小示例

```vue
<BaseTable :columns="columns" :data-source="list">
  <template #cell-status="{ row }">
    <StatusTag :status="row.status" />
  </template>
</BaseTable>
```

- 通用表格负责结构和状态约定，复杂单元格渲染通过局部扩展位接入。

## 常见误区

- 列表卡顿就立刻上虚拟滚动，没有先看重渲染来源。
- 一个响应式筛选对象变动，导致整个表格所有单元格一起更新。
- 基础表格组件把分页、查询、导出、权限、弹窗全包进去。
