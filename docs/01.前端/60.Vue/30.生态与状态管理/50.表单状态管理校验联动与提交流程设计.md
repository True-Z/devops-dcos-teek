# Vue 表单状态管理 校验联动 与提交流程设计

## 阅读建议

- 这页重点不是单独看表单校验，而是把输入状态、校验反馈、提交流程放到同一条链路里理解。

## 核心目标

- 理解表单为什么常常不是“几个 `v-model` 加一个提交按钮”这么简单。

## 表单状态常见分层

| 状态     | 典型内容                       |
| -------- | ------------------------------ |
| 值状态   | 输入值、默认值、回填值         |
| 交互状态 | 聚焦、失焦、是否改动           |
| 校验状态 | 是否通过、错误信息、异步校验中 |
| 提交状态 | 提交中、成功、失败、重试       |

## 为什么要做状态分层

- 因为用户输入、校验反馈、提交成功与失败并不是同一层语义。
- 如果全部混在一个对象里，页面很快会失控。

## 校验联动怎么理解

- 校验不是只能在提交时一次性做。
- 更常见的是：
  - 输入时做基础格式校验
  - 失焦时做字段级提示
  - 提交时做整表兜底校验
  - 必要时做异步校验，比如用户名是否已占用

## 最小示例

```vue
<script setup>
import { reactive, ref } from 'vue'

const form = reactive({
  name: '',
  email: '',
})

const errors = reactive({
  name: '',
  email: '',
})

const submitting = ref(false)

function validate() {
  errors.name = form.name ? '' : '请输入姓名'
  errors.email = /@/.test(form.email) ? '' : '邮箱格式不正确'
  return !errors.name && !errors.email
}
</script>
```

## 提交流程设计主线

1. 提交前做最终校验
2. 提交中锁定按钮或避免重复提交
3. 提交失败给明确错误反馈
4. 提交成功后决定是清空、跳转，还是保留结果态

## 常见误区

- 只在提交时校验，导致用户体验很滞后。
- 校验信息和字段状态强耦合，难以维护。
- 提交中不做幂等保护，用户连续点击产生重复请求。
