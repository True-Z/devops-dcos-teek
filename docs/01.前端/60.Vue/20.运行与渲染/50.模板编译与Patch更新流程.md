# Vue 模板编译与 Patch 更新流程

## 阅读建议

- 这页适合在你已经知道响应式和生命周期后阅读，用来把“数据变更”与“视图更新”真正串起来。

## 核心目标

- 理解 Vue 模板如何变成渲染函数。
- 理解组件更新时为什么不是整页重绘，而是走 patch 和 diff。

## 最小主线

```text
template -> compile -> render function -> vnode -> patch -> DOM update
```

## 模板编译在做什么

- 模板不会直接被浏览器原生理解成 Vue 运行逻辑。
- Vue 会先把模板编译成 render function，再由 render function 生成 vnode。

## vnode 是什么

- vnode 可以理解成 Vue 用来描述界面结构的虚拟节点对象。
- 它不是实际 DOM，而是“更新前后用来比较差异的中间表示”。

## patch 在做什么

- patch 的核心目标不是“重建整棵树”，而是对比新旧 vnode，尽量只更新变化部分。
- 所以 Vue 运行时重点是“差异更新”，不是“全量重渲染”。

## diff 怎么理解

- diff 可以理解成：新旧 vnode 对比后，找出哪些节点需要新增、删除、移动或更新。
- 列表里 `key` 很重要，就是因为它帮助 diff 更稳定地识别节点身份。

## 更新过程主线

1. 响应式数据变化
2. 触发组件重新执行 render
3. 生成新的 vnode
4. 新旧 vnode 进入 patch 对比
5. 只把有差异的部分同步到真实 DOM

## 为什么要强调模板编译

- 因为面试里常会问：Vue 是运行时框架，为什么还能写模板。
- 更准确的回答是：模板语法只是开发体验入口，最终仍会被编译成运行时可执行结构。

## 常见误区

- 以为数据一变就整页重新渲染。
- 以为 vnode 就是 DOM。
- 只记“Vue 有 diff”，但说不清它在解决什么问题。
