# Vue 异步数据获取策略与 SEO 落地

## 阅读建议

- 这页重点不是只看“接口什么时候发”，而是把获取时机、渲染链路和 SEO 结果一起看。

## 核心目标

- 理解 Vue 应用里异步数据为什么会直接影响首屏、可交互时间和搜索收录。

## 异步数据获取的常见时机

| 时机           | 适合场景             | 风险             |
| -------------- | -------------------- | ---------------- |
| 组件挂载后     | CSR 页面、非关键数据 | 首屏容易先空后补 |
| 路由进入前     | 页面级关键数据       | 容易拉长跳转等待 |
| 服务端渲染阶段 | 首屏 SEO 关键内容    | 服务端压力更高   |
| 客户端二次补拉 | 个性化、弱关键数据   | 要处理闪动与占位 |

## 推荐主线

1. 先区分数据是不是首屏关键数据。
2. 首屏关键数据优先考虑在页面渲染前拿到。
3. 非关键数据可以延后，避免把主链路拖长。
4. 个性化或仅登录后可见内容，不必强行纳入 SEO 链路。

## CSR 下怎么做

- 如果是纯客户端渲染，搜索引擎是否能拿到内容很依赖执行环境。
- 对于真正依赖 SEO 的页面，纯 CSR 往往不够稳。

## SSR / SSG 下怎么做

- SSR 更适合内容动态、但又要求首屏和 SEO 的页面。
- SSG 更适合结构稳定、可预生成的内容页。
- 关键点不是“上哪种模式”，而是页面内容是否值得进入服务端链路。

## SEO 落地重点

| 维度     | 需要关注什么                            |
| -------- | --------------------------------------- |
| 页面内容 | 标题、描述、正文首屏可见                |
| 元信息   | `title`、`meta description`、Open Graph |
| 路由结构 | 稳定 URL、合理层级                      |
| 内容时机 | 爬虫抓取时能否拿到主体内容              |

## 最小示例

```text
首屏关键内容 -> 尽量在服务端或渲染前拿到
非关键内容 -> 可在客户端延后补拉
```

## 常见误区

- 把所有数据都塞进首屏接口，导致主链路过重。
- 只做了页面标题，忽略正文主体内容实际不可抓取。
- 把个性化数据也强行放进 SSR，增加复杂度却收益很低。
