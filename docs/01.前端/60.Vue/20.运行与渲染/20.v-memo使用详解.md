# Vue v-memo 使用详解

## 阅读建议

- 这页适合在你已经遇到“列表子树频繁重复更新”时阅读。
- `v-memo` 不是常规开发默认必用能力，它更偏性能优化工具。

## 它解决什么问题

- 当某个子树在大多数更新中其实不需要重新 patch，`v-memo` 可以让 Vue 在依赖值没变时跳过这段子树的更新。

## 最小示例

```vue
<template>
  <div v-for="item in list" :key="item.id" v-memo="[item.id, item.selected]">
    <RowItem :item="item" />
  </div>
</template>
```

- 如果 `item.id` 和 `item.selected` 没变，Vue 会优先复用这段子树的上次结果。

## 和其他能力的区别

| 能力       | 更适合解决什么问题       |
| ---------- | ------------------------ |
| `computed` | 计算结果缓存             |
| `v-once`   | 永不再更新的静态片段     |
| `v-memo`   | 条件稳定时跳过子树 patch |

## 原理理解

- `v-memo` 会让运行时在 patch 子树前先比较 memo 依赖数组。
- 依赖没变时，Vue 可以跳过这段子树的重复更新。
- 所以它优化的是“更新成本”，不是“首次渲染成本”。

## 使用建议

- 优先用在大列表、复杂子树、局部高频更新场景。
- 依赖数组要精确，既不能少到漏更新，也不要多到失去意义。
- 如果只是普通组件更新，先不要为了“看起来高级”就上 `v-memo`。

## 常见误区

- 把 `v-memo` 当成任何页面都要加的默认优化。
- 依赖数组写得过宽，导致几乎每次都重新更新。
- 依赖数组写得过窄，导致视图不更新。
