# Vue 错误边界与异步组件失败恢复

## 阅读建议

- 这页重点不是只看报错捕获，而是理解“页面局部失败时，如何避免整页体验一起崩掉”。

## 核心目标

- 理解 Vue 应用里错误如何被捕获、隔离、上报和恢复。

## 错误边界在解决什么问题

- 当组件树某一段运行失败时，错误边界的价值是让问题被局部兜底，而不是直接扩散成整页不可用。
- 它更像“故障隔离点”，而不是简单的 `try/catch` 替代品。

## 常见错误来源

| 类型           | 典型场景                           |
| -------------- | ---------------------------------- |
| 渲染错误       | 模板依赖数据为空、运行时表达式异常 |
| 生命周期错误   | `mounted` / `updated` 中抛错       |
| 异步组件失败   | 懒加载 chunk 加载失败、网络断开    |
| 业务副作用错误 | 请求结果处理异常、状态同步异常     |

## Vue 里常见的处理位置

| 位置                      | 更适合处理什么        |
| ------------------------- | --------------------- |
| `onErrorCaptured`         | 组件树局部错误拦截    |
| `app.config.errorHandler` | 全局兜底与统一上报    |
| 路由级错误页              | 页面级降级展示        |
| 异步组件 `errorComponent` | 懒加载失败时的回退 UI |

## `onErrorCaptured` 怎么理解

- 它更适合在局部组件边界上拦截子树错误。
- 这样可以把错误转成局部提示、兜底 UI 或上报逻辑。

```ts
import { onErrorCaptured, ref } from 'vue'

const hasError = ref(false)

onErrorCaptured((error) => {
  hasError.value = true
  console.error(error)
  return false
})
```

- 面试里常见追问：为什么它更像“组件级错误边界”，而不是全局错误处理唯一入口。

## 异步组件失败怎么恢复

- 异步组件失败最常见的不是组件代码错，而是资源加载失败。
- 所以恢复策略重点通常是：
  - 给用户清晰提示
  - 提供重试入口
  - 做失败上报
  - 必要时回退到同步可用版本或占位内容

## 最小示例

```ts
import { defineAsyncComponent } from 'vue'

const AsyncPanel = defineAsyncComponent({
  loader: () => import('./Panel.vue'),
  errorComponent: {
    template: '<div>加载失败，请重试</div>',
  },
})
```

## 失败恢复主线

1. 先区分是组件逻辑错误，还是资源加载错误。
2. 局部错误优先局部兜底，不要动不动跳整页错误页。
3. 所有关键错误都要带上版本、路由、环境信息上报。
4. 对异步组件失败，最好给重试或回退策略。

## 常见误区

- 以为全局 `errorHandler` 配了就不需要局部错误隔离。
- 异步组件失败只打印日志，不给用户任何反馈。
- 错误上报没有版本和路由信息，线上无法定位。
