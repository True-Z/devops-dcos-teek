# Vue 事件与事件修饰符

## 阅读建议

- 这页重点不是背指令语法，而是理解“修饰符在帮你改什么事件处理逻辑”。
- 如果你当前主要想解决“阻止事件向上传递”，先看 `.stop`。

## 核心目标

- 理解事件修饰符如何减少模板里的手动事件控制。

## 常见修饰符总表

| 修饰符     | 作用                              | 常见场景               |
| ---------- | --------------------------------- | ---------------------- |
| `.stop`    | 阻止冒泡                          | 子元素点击不影响父元素 |
| `.prevent` | 阻止默认行为                      | 表单提交、链接跳转     |
| `.capture` | 捕获阶段触发                      | 提前拦截事件           |
| `.self`    | 只在自身触发                      | 避免子节点误触发       |
| `.once`    | 只触发一次                        | 首次确认、初始化动作   |
| `.passive` | 告诉浏览器不调用 `preventDefault` | 滚动性能优化           |

## 阻止事件向上传递

```vue
<template>
  <div class="card" @click="openCard">
    <button @click.stop="removeItem">删除</button>
  </div>
</template>
```

- `.stop` 本质上就是帮你在事件处理里调用 `event.stopPropagation()`。
- 这样点击按钮时，不会继续冒泡到外层卡片的点击逻辑。

## 组合写法

```vue
<form @submit.prevent="submit">
  <button @click.stop.once="confirm">确认</button>
</form>
```

- 修饰符可以组合，但要注意语义是否清晰。
- 组合越多，越应该确认这段模板是否已经过于复杂。

## 原理理解

- Vue 在编译模板时会把修饰符转换成对应的事件包装逻辑。
- 所以它不是“浏览器新增语法”，而是框架帮你生成了更明确的事件处理代码。

## 常见误区

- 把 `.stop` 和 `.prevent` 混为一谈。
- 看到事件冲突就一路叠修饰符，而不去梳理事件结构。
- 在滚动事件里误用 `.passive` 后还想调用 `preventDefault()`。
