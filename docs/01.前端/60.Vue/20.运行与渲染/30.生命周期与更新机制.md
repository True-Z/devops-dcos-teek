# Vue 生命周期与更新机制

## 阅读建议

- 这页更适合按“创建 -> 挂载 -> 更新 -> 卸载”来记，不要死背钩子表。

## 生命周期主线

| 阶段 | 关键问题                   |
| ---- | -------------------------- |
| 创建 | 数据和实例什么时候准备好   |
| 挂载 | 什么时候能拿到真实 DOM     |
| 更新 | 数据变化后什么时候重新渲染 |
| 卸载 | 什么时候做清理             |

## Composition API 视角

- `setup` 是进入组件逻辑的起点。
- `onMounted` 适合依赖真实 DOM 的逻辑。
- `onUpdated` 适合在更新后观察结果，但不适合反复触发额外重逻辑。
- `onUnmounted` 适合解绑事件、清理定时器、释放订阅。

## 更新机制怎么理解

- 数据变化不会立即同步把所有 DOM 全重建。
- Vue 会先标记需要更新的组件，再进入 patch 过程，只对变化部分做比对和更新。
- 所以组件更新重点不是“重新跑一遍模板”这么简单，而是“最小化差异更新”。

## 为什么会问 `nextTick`

- 因为数据更新后，DOM 更新通常是异步批处理的。
- `nextTick` 适合在本轮视图更新完成后再读取最新 DOM。

## 常见追问

- 为什么 mounted 后才能安全访问 DOM。
- 为什么 updated 里不能无脑再改响应式数据。
- 为什么组件卸载时必须清理副作用。
