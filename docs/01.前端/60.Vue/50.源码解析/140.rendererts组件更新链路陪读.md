# renderer.ts 组件更新链路陪读

## 阅读建议

- 这页只聚焦 `renderer.ts` 里“组件为什么会更新、更新时走哪条链路”，不展开完整 patch 全细节。

## 核心目标

- 看完后能把组件更新链路说成一条主线：组件 render effect 被响应式变化触发，经 scheduler 调度，再进入 render / patch。

## 先记住一句话

- 组件更新并不是一个独立系统，它本质是“组件 render 被包装成一个 effect”，然后接进响应式和 scheduler 主线。

## 最小主线

```text
setup component -> create render effect -> render vnode -> patch -> 响应式变化 -> scheduler -> render effect 再执行
```

## 先带着这几个问题去看

1. 组件 render 为什么也能被当成 effect。
2. 初次挂载和后续更新的分界在哪里。
3. 响应式变化后，组件为什么不是立刻同步重渲染。
4. 新旧 vnode 在哪里接到 patch。

## 第一层：为什么组件 render 能接入响应式

- 因为组件 render 过程中会读取响应式状态。
- 只要把 render 包装成 effect，它读取的数据就能被 `track` 收集。
- 后续这些数据变化时，render effect 就会被重新调度。

## 第二层：组件更新链路里最重要的角色

| 角色          | 负责什么                        |
| ------------- | ------------------------------- |
| 组件实例      | 保存 props、slots、setup 状态等 |
| render effect | 执行 render，产出 vnode         |
| scheduler     | 控制 render effect 的执行时机   |
| patch         | 比较新旧 vnode 并更新真实 DOM   |

## 第三层：初次挂载和更新怎么分

| 阶段     | 更关注什么                                    |
| -------- | --------------------------------------------- |
| 初次挂载 | 创建实例、执行 setup、首次 render、首次 patch |
| 后续更新 | 依赖变化后调度 render effect，再走 patch      |

## 第四层：render effect 真正在做什么

1. 执行组件 render。
2. 生成当前这一次的新 vnode 子树。
3. 和上一次子树对比。
4. 调用 patch 只更新变化部分。

## 最小示例

```vue
<template>
  <div>{{ count }}</div>
</template>
```

- 这段模板最终会变成 render 逻辑。
- render 读取 `count` 时会被 `track`。
- `count` 变化后，组件对应的 render effect 会进入调度更新链路。

## 第五层：为什么更新要走 scheduler

- 组件更新是非常常见、也可能非常频繁的 job。
- 如果每次变化都同步 render + patch，页面会产生大量重复更新。
- 所以 renderer 会把组件更新 effect 接到 scheduler，让更新批量合并。

## 第六层：读 `renderer.ts` 时别一上来就迷失在 patch 分支里

| 更推荐先看什么              | 先回答什么问题                 |
| --------------------------- | ------------------------------ |
| 组件 render effect 创建位置 | render effect 是怎么建起来的   |
| update component 相关主线   | 更新时如何重新进入 render      |
| patch 子树位置              | 新旧 vnode 是在哪里对比的      |
| scheduler 对接点            | 为什么组件更新走的是 job queue |

## 一句话串起来

```text
renderer.ts 负责把“响应式变化”最终落到“组件 render 重新执行并 patch 到 DOM”
```

## 常见误区

- 一上来就盯 diff 细节，结果没看懂组件更新主线。
- 以为组件更新和 watcher 更新是两套完全无关系统。
- 只知道 patch，很少把 render effect 和 scheduler 一起看。
