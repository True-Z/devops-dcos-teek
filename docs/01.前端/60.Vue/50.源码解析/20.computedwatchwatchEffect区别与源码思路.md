# computed watch watchEffect 区别与源码思路

## 阅读建议

- 这页重点不是只记结论，而是理解三者为什么都和 `effect` 有关，却承担完全不同的职责。

## 核心目标

- 看完后能从“派生值 / 副作用 / 依赖收集方式”三个维度区分 `computed`、`watch`、`watchEffect`。

## 一张表先看结论

| 能力          | 本质定位             | 依赖收集方式      | 是否缓存 | 是否适合副作用 |
| ------------- | -------------------- | ----------------- | -------- | -------------- |
| `computed`    | 派生值               | getter 执行时收集 | 是       | 不适合         |
| `watch`       | 精确观察后执行回调   | 明确指定依赖源    | 否       | 适合           |
| `watchEffect` | 自动观察后执行副作用 | 执行时自动收集    | 否       | 适合           |

## `computed` 的源码思路怎么理解

- `computed` 可以理解成一个“懒执行 + 可缓存”的特殊 effect。
- 它不会像普通副作用那样一变就立刻干活，而是先把自己标成脏。
- 当外部再次读取 `.value` 时，才重新求值。

## `watch` 的源码思路怎么理解

- `watch` 本质上也是建立一个 effect，只是它更强调“指定观察谁”。
- 它会先拿到依赖源的最新结果，再在变化后调用回调。
- 它适合需要新旧值、清理逻辑、`flush` 时机控制的场景。

## `watchEffect` 的源码思路怎么理解

- `watchEffect` 更像“副作用版自动收集依赖”。
- 它执行时会把内部读取到的响应式数据都纳入依赖。
- 所以它写起来很快，但依赖边界没有 `watch` 明确。

## 处理顺序对比

| 步骤 | `computed`                       | `watch`                                | `watchEffect`              |
| ---- | -------------------------------- | -------------------------------------- | -------------------------- |
| 1    | 创建带 getter 的特殊 effect      | 创建观察 effect                        | 创建副作用 effect          |
| 2    | 初始通常惰性，不一定立刻求值     | 收集指定依赖源                         | 立即执行并自动收集依赖     |
| 3    | 依赖变化时只标脏                 | 依赖变化时调度回调                     | 依赖变化时重新执行副作用   |
| 4    | 下次读取 `.value` 才真正重新计算 | 回调可拿到新旧值、清理函数、flush 时机 | 执行逻辑中再次收集当前依赖 |

## 最小示例

```ts
const count = ref(1)

const doubled = computed(() => count.value * 2)

watch(count, (newValue, oldValue) => {
  console.log('watch', newValue, oldValue)
})

watchEffect(() => {
  console.log('watchEffect', count.value)
})
```

## 这个例子该怎么理解

- `doubled` 只有在被读取时才真正计算，并且会缓存结果。
- `watch` 明确观察 `count`，变化后拿到新旧值做副作用。
- `watchEffect` 自动依赖 `count.value`，只要它变就重新跑。

## 什么时候该用谁

| 场景                         | 更适合什么    |
| ---------------------------- | ------------- |
| 模板里展示派生值             | `computed`    |
| 需要请求、日志、同步外部系统 | `watch`       |
| 快速写局部副作用             | `watchEffect` |
| 需要拿新旧值                 | `watch`       |
| 需要明确控制依赖             | `watch`       |

## 常见误区

- 用 `watch` 来计算模板派生值，结果代码变绕。
- 在 `computed` 里做请求或 DOM 操作，把派生值和副作用混在一起。
- 用 `watchEffect` 写很重的异步逻辑，却不知道它到底依赖了什么。
