# 手写迷你 Vue3 响应式系统

## 阅读建议

- 这页重点不是造一个完整 Vue，而是用极简代码把 `track -> trigger -> effect` 这条主线亲手跑通。

## 核心目标

- 看完后能用一个最小实现把 Vue3 响应式的核心流程讲明白，再回头看源码时更容易对上概念。

## 最小目标

- 我们只实现三个核心能力：
  - `reactive`
  - `effect`
  - `track` / `trigger`

## 第一步：准备依赖桶

```ts
const bucket = new WeakMap<object, Map<PropertyKey, Set<Function>>>()

let activeEffect: Function | null = null
```

- `bucket` 用来记录：哪个对象的哪个 key，被哪些 effect 用到了。

## 第二步：实现 `effect`

```ts
function effect(fn: Function) {
  const effectFn = () => {
    activeEffect = effectFn
    fn()
    activeEffect = null
  }

  effectFn()
  return effectFn
}
```

- 核心点只有一个：执行 `fn` 时，当前 active effect 是谁。

## 第三步：实现 `track`

```ts
function track(target: object, key: PropertyKey) {
  if (!activeEffect) return

  let depsMap = bucket.get(target)
  if (!depsMap) {
    depsMap = new Map()
    bucket.set(target, depsMap)
  }

  let deps = depsMap.get(key)
  if (!deps) {
    deps = new Set()
    depsMap.set(key, deps)
  }

  deps.add(activeEffect)
}
```

- 读取时如果当前有 active effect，就把它记录进依赖集合。

## 第四步：实现 `trigger`

```ts
function trigger(target: object, key: PropertyKey) {
  const depsMap = bucket.get(target)
  if (!depsMap) return

  const effects = depsMap.get(key)
  if (!effects) return

  effects.forEach((effectFn) => effectFn())
}
```

- 写入时把依赖这个 key 的 effect 再执行一遍。

## 第五步：实现 `reactive`

```ts
function reactive<T extends object>(target: T): T {
  return new Proxy(target, {
    get(target, key, receiver) {
      track(target, key)
      return Reflect.get(target, key, receiver)
    },
    set(target, key, value, receiver) {
      const result = Reflect.set(target, key, value, receiver)
      trigger(target, key)
      return result
    },
  })
}
```

- 这样读写代理对象时，就能接到依赖系统。

## 最小可运行示例

```ts
const state = reactive({ count: 0 })

effect(() => {
  console.log('count =', state.count)
})

state.count++
state.count++
```

## 运行过程怎么理解

1. `effect` 首次执行，读取 `state.count`
2. `get` 触发 `track`
3. `track` 把当前 effect 记录到 `count` 对应的依赖集合
4. `state.count++` 触发 `set`
5. `set` 进入 `trigger`
6. `trigger` 把依赖它的 effect 再执行一遍

## 这个迷你版本缺了什么

| 能力             | 为什么这里没做                     |
| ---------------- | ---------------------------------- |
| cleanup          | 先只保留主线，避免第一次就过载     |
| scheduler        | 先理解“触发更新”，再理解“何时更新” |
| computed         | 它本质是特殊 effect，可后补        |
| watch            | 它本质是 effect 的包装层           |
| 嵌套 effect 边界 | 属于进阶问题                       |

## 为什么这个练习有用

- 因为你会发现 Vue3 响应式主线其实并不神秘。
- 真正的难点不是“有多复杂”，而是后续为性能、边界和可维护性补进去的调度、cleanup、缓存、watcher 包装。

## 下一步怎么从迷你版过渡到源码版

1. 先补 cleanup，理解为什么依赖不能一直累加。
2. 再补 scheduler，理解为什么更新不必同步执行。
3. 再补 computed，理解 lazy 和 dirty。
4. 最后再看 watch 怎么在 effect 外面包一层观察逻辑。

## 常见误区

- 手写完最小版就以为源码只是“更长一点”。
- 只看到 Proxy，而没看到真正关键的是依赖桶和 active effect。
- 还没理解最小主线，就急着上 computed 和 watch。
