# Vue3 源码文件定位图

## 阅读建议

- 这页重点不是穷举整个仓库，而是帮你快速定位“响应式、watch、scheduler、组件更新、patch”分别主要看哪一块。

## 核心目标

- 看完后能建立一张源码地图：带着问题去找文件，而不是在仓库里盲目翻目录。

## 最推荐的定位顺序

1. 先看 `reactivity`，理解依赖收集和触发更新。
2. 再看 `runtime-core` 里和 scheduler、watch、组件更新有关的逻辑。
3. 最后再看 renderer、patch 和编译相关内容。

## 一张表看主要模块

| 关注问题                       | 优先关注什么目录 / 文件方向                                                                                      |
| ------------------------------ | ---------------------------------------------------------------------------------------------------------------- |
| `reactive` / `ref` 怎么实现    | `packages/reactivity/src/`                                                                                       |
| `effect` / `track` / `trigger` | `packages/reactivity/src/effect.ts`、`packages/reactivity/src/dep.ts`、`packages/reactivity/src/baseHandlers.ts` |
| `computed` 怎么做缓存          | `packages/reactivity/src/computed.ts`                                                                            |
| `watch` / `watchEffect`        | `packages/runtime-core/src/apiWatch.ts`                                                                          |
| scheduler / job queue          | `packages/runtime-core/src/scheduler.ts`                                                                         |
| 组件更新怎么接进来             | `packages/runtime-core/src/renderer.ts`                                                                          |
| vnode / patch / diff           | `packages/runtime-core/src/renderer.ts`                                                                          |
| 组件实例和 setup 流程          | `packages/runtime-core/src/component.ts`                                                                         |
| 编译入口                       | `packages/compiler-core/`、`packages/compiler-dom/`                                                              |

## 如果你现在主要看响应式

| 第一步看什么                     | 想回答什么问题                     |
| -------------------------------- | ---------------------------------- |
| `reactivity/src/effect.ts`       | effect 是怎么被创建、运行和停止的  |
| `reactivity/src/baseHandlers.ts` | 读写代理时什么时候 track / trigger |
| `reactivity/src/dep.ts`          | 依赖集合怎么组织和触发             |
| `reactivity/src/computed.ts`     | computed 为什么有缓存和脏标记      |

## 如果你现在主要看 watch 和 scheduler

| 第一步看什么                    | 想回答什么问题                      |
| ------------------------------- | ----------------------------------- |
| `runtime-core/src/apiWatch.ts`  | watch 怎么把依赖源包装成观察逻辑    |
| `runtime-core/src/scheduler.ts` | job queue 怎么去重、排序、flush     |
| `runtime-core/src/renderer.ts`  | 组件 render effect 怎么进入调度链路 |

## 最小阅读路径

```text
effect.ts -> baseHandlers.ts -> dep.ts -> computed.ts -> apiWatch.ts -> scheduler.ts -> renderer.ts
```

## 每个文件优先抓什么

| 文件              | 优先抓的主线                       |
| ----------------- | ---------------------------------- |
| `effect.ts`       | effect 创建、运行、清理、stop      |
| `baseHandlers.ts` | 代理对象读写时如何接到依赖系统     |
| `dep.ts`          | dep 如何记录 effect 并触发更新     |
| `computed.ts`     | lazy、dirty、缓存                  |
| `apiWatch.ts`     | `watch` / `watchEffect` 的包装逻辑 |
| `scheduler.ts`    | queue、flush、执行顺序             |
| `renderer.ts`     | 组件更新 effect、patch、渲染主流程 |

## 怎么避免读源码时迷路

1. 不要一开始就从 `renderer.ts` 硬啃到尾。
2. 先带着问题读，例如“watch 为什么能拿到新旧值”。
3. 先抓模块职责，再看具体分支和边界处理。
4. 先把 `reactivity` 和 `runtime-core` 连起来，再碰编译层。

## 常见误区

- 只知道目录名，不知道每个文件是回答什么问题。
- 先看 patch 和 diff，结果前面的 effect / scheduler 主线没建立起来。
- 试图第一次就读完全部实现细节，导致主线感丢失。
