# Vue 3.4 与 3.5 侦听器变化梳理

## 阅读建议

- 这页聚焦侦听器相关变化、使用影响和源码主线变化，不做逐版本全量 diff。

## 核心目标

- 看完后能知道：3.4 到 3.5 在 `watch` / `watchEffect` 上，哪些能力更好用了，以及这些变化对理解源码有什么帮助。

## 先抓主结论

| 版本 | 你更该关注什么                            |
| ---- | ----------------------------------------- |
| 3.4  | `once` 等侦听器能力更完善，侦听控制更明确 |
| 3.5  | 清理、副作用边界、深度控制等体验更自然    |

## 3.4 里更值得记的点

- `watch` 的一次性监听能力更明确，适合“只响应第一次变化”的场景。
- 侦听器选项在语义上更完整，使用意图更容易表达。
- 对读源码的人来说，重点是理解 watcher 已经不只是“变化后回调”，而是一套可配置的副作用调度接口。

## 3.5 里更值得记的点

- 清理逻辑的表达更顺手，副作用生命周期边界更清晰。
- 深度监听控制更细，避免很多“想监听又怕太重”的尴尬情况。
- 对读源码的人来说，重点不是背 API，而是看到 Vue 在把 watcher 往“更可控的副作用系统”推进。

## 使用层面的影响

| 场景             | 3.4 / 3.5 之后更稳的思路                   |
| ---------------- | ------------------------------------------ |
| 只需一次的监听   | 明确使用一次性监听，而不是手动 stop        |
| 有副作用清理逻辑 | 更强调把清理逻辑和 watcher 绑在一起        |
| 深层对象监听     | 优先考虑更细粒度的依赖源，而不是无脑深监听 |
| 异步副作用       | 更重视清理时机和过期副作用处理             |

## 源码主线变化怎么理解

- 主干并没有变：依旧是建立 effect、收集依赖、变化后调度回调。
- 更大的变化在 watcher 包装层：选项更丰富、清理时机更明确、边界更可控。
- 所以阅读源码时，还是先盯住 effect 和 scheduler，再看 watcher 怎么在外面包一层能力。

## 最小示例

```ts
watch(source, callback, {
  once: true,
})
```

- 这种能力的重点不在语法本身，而在于 watcher 从“单纯回调”变成了“带调度语义的观察器”。

## 阅读源码时怎么抓重点

1. 先理解 watcher 最终仍然依附于 effect 系统。
2. 再看依赖源标准化、回调封装、清理注册这些包装层逻辑。
3. 最后再看 `flush`、深度遍历、清理回调等增强能力。

## 常见误区

- 把 3.4 / 3.5 差异当成完全重写了一套 watcher。
- 只记 API 新增项，却说不清背后还是 effect + scheduler 主线。
- 看到深度监听能力增强，就继续无脑监听整个大对象。
