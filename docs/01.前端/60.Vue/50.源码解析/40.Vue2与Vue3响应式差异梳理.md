# Vue2 与 Vue3 响应式差异梳理

## 阅读建议

- 这页主要用于建立对照感：Vue2 不要求你深读源码，但要知道为什么 Vue3 的响应式边界更自然。

## 核心目标

- 看完后能用对照表说清：Vue2 和 Vue3 在拦截方式、依赖收集、数组处理和能力边界上的核心区别。

## 一张表先看核心差异

| 维度         | Vue2                      | Vue3                         |
| ------------ | ------------------------- | ---------------------------- |
| 拦截方式     | `Object.defineProperty`   | `Proxy`                      |
| 新增属性处理 | 需要 `Vue.set` 等补救     | 天然可拦截                   |
| 数组处理     | 依赖重写数组方法          | 可直接拦截更多操作           |
| 依赖收集单位 | getter / setter + watcher | `track` / `trigger` + effect |
| 表达能力     | 有些场景边界比较别扭      | 更统一、更自然               |

## Vue2 的主线怎么理解

- Vue2 主要是把对象属性转换成 getter / setter。
- 当 getter 被读取时收集 watcher。
- 当 setter 被写入时通知 watcher 更新。
- 它的核心思想和 Vue3 一样都是依赖收集 + 触发更新，只是实现手段受限更多。

## Vue3 为什么更自然

- `Proxy` 可以从对象外层统一拦截读取、写入、删除、枚举等行为。
- 响应式逻辑不用再到处补丁式处理新增属性和数组索引。
- 依赖系统被抽象得更统一，`computed`、`watch`、组件更新更容易放进同一主线里理解。

## 阅读源码时该怎么分配精力

| 目标                     | 更建议怎么学                   |
| ------------------------ | ------------------------------ |
| 想理解 Vue3 当前主线     | 重点放在 Vue3                  |
| 想知道为什么 Vue3 更舒服 | 用 Vue2 做对照即可             |
| 想解释历史包袱           | 关注 Vue2 的数组与属性拦截限制 |
| 想解释设计升级           | 关注 Vue3 如何统一 effect 主线 |

## 常见误区

- 以为 Vue2 和 Vue3 是两套完全不同思想。
- 只记 `defineProperty` 和 `Proxy` 这两个词，却说不清它们分别限制了什么。
- 把 Vue2 的历史兼容问题误当成 Vue3 当前主线问题。
