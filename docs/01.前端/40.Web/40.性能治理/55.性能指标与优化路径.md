# Web 性能指标与优化路径

## 核心目标

- 从“感觉慢”转为“指标可量化、优化可追踪”。

## 关键指标

| 指标方向   | 关注点                 | 优化方向                   |
| ---------- | ---------------------- | -------------------------- |
| 加载性能   | 首屏与关键资源到达时间 | 资源体积、缓存、传输策略   |
| 交互性能   | 输入到响应的延迟       | 主线程长任务、事件处理开销 |
| 渲染稳定性 | 页面是否抖动           | 布局稳定、图片尺寸占位     |

## 常见术语速查

| 术语      | 含义                               | 详情链接                                                                          |
| --------- | ---------------------------------- | --------------------------------------------------------------------------------- |
| LCP       | 最大内容绘制，衡量主要内容出现速度 | [web.dev LCP](https://web.dev/articles/lcp)                                       |
| INP       | 交互到下一次绘制，衡量交互延迟     | [web.dev INP](https://web.dev/articles/inp)                                       |
| CLS       | 累积布局偏移，衡量页面抖动         | [web.dev CLS](https://web.dev/articles/cls)                                       |
| Long Task | 主线程长任务，常导致卡顿           | [Long Tasks API](https://developer.mozilla.org/zh-CN/docs/Web/API/Long_Tasks_API) |

## 优化路径建议

1. 先测量：建立基线与监控。
2. 再定位：明确瓶颈在网络、脚本还是渲染。
3. 后治理：按收益排序逐项优化。
4. 持续回归：防止版本迭代性能回退。

## 最小示例

### 使用浏览器性能 API 记录首屏耗时

```js
window.addEventListener('load', () => {
  const entries = performance.getEntriesByType('navigation')
  const first = entries[0]

  console.log('domContentLoaded', first?.domContentLoadedEventEnd)
  console.log('loadEventEnd', first?.loadEventEnd)
})
```

- 这个示例适合建立最初的性能感知，不需要额外接入监控平台。

### 优化路径速查表

| 问题现象 | 优先排查               | 常见动作                |
| -------- | ---------------------- | ----------------------- |
| 首屏慢   | 静态资源体积、缓存命中 | 压缩、分包、CDN、懒加载 |
| 交互卡   | 主线程长任务           | 拆分任务、减少同步计算  |
| 页面抖动 | 图片/容器尺寸未预留    | 固定尺寸、骨架屏、占位  |

## 常见误区

- 只做打包压缩，不看运行时瓶颈。
- 只盯平均值，忽略尾部慢请求。
- 无监控直接优化，难以证明收益；涉及指标定义可继续看 [Core Web Vitals](https://web.dev/vitals/)。
