# Web 速查要点

## 核心定位

- Web 领域核心是“请求链路 + 浏览器机制 + 安全与性能”。
- 前端线上稳定性，很大程度取决于对缓存、网络与安全策略的理解；具体可继续看 [Web 渲染流程与关键渲染路径](/fe/web-rendering-critical-path)、[Web 浏览器存储方案](/fe/web-storage-strategy)、[Web 跨域与安全方案](/fe/web-cors-security)、[Web 性能指标与优化路径](/fe/web-performance-path)。

## 请求链路速记

| 阶段      | 关键点             | 排查方向                 |
| --------- | ------------------ | ------------------------ |
| DNS       | 域名解析路径与缓存 | 解析延迟、污染、失败重试 |
| 连接建立  | TCP/TLS 握手       | RTT、证书、连接复用      |
| HTTP 请求 | 方法、头、缓存策略 | 状态码、缓存命中、跨域   |
| 渲染      | 关键渲染路径       | 阻塞资源、首屏速度       |

## 缓存策略

- 静态资源优先强缓存，接口数据按业务需求协商缓存。
- `Cache-Control` 优先级高于 `Expires`。
- 缓存不是“越久越好”，要兼顾发布回收策略。

## 跨域与安全

- 跨域优先通过服务端策略统一处理（CORS/网关）。
- 对用户输入与富文本输出做 XSS 防护。
- 涉及登录态的请求关注 CSRF 与 SameSite 策略。

## 连接选型

- 高频双向实时：优先 WebSocket。
- 低频状态刷新：可用短轮询/长轮询。
- 选型核心是实时性、服务器成本、实现复杂度三者平衡。

## 最小示例

```js
fetch('/api/user/profile')
  .then((res) => res.json())
  .then((data) => console.log(data))
```

- 这是最基础的 Web 请求链路：发请求、收响应、解析数据；深入后再考虑缓存、跨域、安全与性能。

## 常见误区

- 把开发代理当成线上代理方案。
- 忽略状态码语义，只看“有无返回值”。
- 只优化接口耗时，不优化渲染链路。
