# Web 跨域与安全方案

## 核心目标

- 在保证业务可用的同时，最小化安全暴露面。

## 模块定位

- 这页更偏“风险控制方案”，适合和服务端、网关策略一起看。

## 跨域策略要点

- 开发环境代理只用于本地联调，不等于线上安全策略。
- 线上跨域应由网关/服务端统一配置 [CORS](https://developer.mozilla.org/zh-CN/docs/Web/HTTP/CORS)。
- 预检请求失败优先检查方法、请求头、凭证配置。

## 最小示例

### 触发预检请求的常见场景

```js
fetch('https://api.example.com/user', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
    Authorization: 'Bearer token',
  },
  body: JSON.stringify({ id: 1 }),
})
```

- 这类请求通常会先发起 `OPTIONS` 预检，因为它包含了自定义请求头和 JSON 请求体。

### 开发代理与线上策略的区别

```js
server: {
  proxy: {
    '/api': {
      target: 'https://example.com',
      changeOrigin: true
    }
  }
}
```

- 这只能解决本地开发联调，不代表线上已经解决跨域。

## 前端安全最小清单

| 风险     | 典型场景            | 基础防护                              |
| -------- | ------------------- | ------------------------------------- |
| XSS      | 富文本、拼接 HTML   | 输出转义、白名单过滤、CSP             |
| CSRF     | Cookie 自动携带请求 | SameSite、Token 校验                  |
| 点击劫持 | 页面被 iframe 套壳  | X-Frame-Options / CSP frame-ancestors |

## 常见安全术语速查

| 术语 | 核心含义                       | 详情链接                                                                          |
| ---- | ------------------------------ | --------------------------------------------------------------------------------- |
| CORS | 浏览器跨源资源共享机制         | [MDN CORS](https://developer.mozilla.org/zh-CN/docs/Web/HTTP/CORS)                |
| XSS  | 恶意脚本注入到页面执行         | [MDN XSS](https://developer.mozilla.org/zh-CN/docs/Glossary/Cross-site_scripting) |
| CSRF | 利用登录态伪造用户请求         | [MDN CSRF](https://developer.mozilla.org/en-US/docs/Glossary/CSRF)                |
| CSP  | 内容安全策略，限制资源执行来源 | [MDN CSP](https://developer.mozilla.org/zh-CN/docs/Web/HTTP/CSP)                  |

## 实施建议

- 安全策略文档化，避免每个项目重复摸索。
- 关键接口做权限最小化与审计日志。
- 安全问题优先“阻断风险”再“优化体验”。
