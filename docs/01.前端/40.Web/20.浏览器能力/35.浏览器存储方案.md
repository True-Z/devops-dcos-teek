# Web 浏览器存储方案

## 选型目标

- 在容量、生命周期、安全性、可用性之间找到平衡。

## 模块定位

- 这页重点是“存什么、放哪里、为什么”，适合和登录状态、缓存策略一起理解。

## 常见存储对比

| 方式           | 适合存什么               | 生命周期       | 风险点                        |
| -------------- | ------------------------ | -------------- | ----------------------------- |
| Cookie         | 会话标识、服务端读写信息 | 可配置过期时间 | 体积小、随请求发送、需防 CSRF |
| localStorage   | 持久化轻量配置           | 长期保存       | 容量有限、XSS 风险            |
| sessionStorage | 会话级临时状态           | 页签关闭即失效 | 不适合跨页签持久场景          |
| IndexedDB      | 大量结构化数据           | 长期保存       | API 相对复杂                  |

## 实施建议

- 敏感信息不直接明文存储在可读存储中。
- 统一封装存储层，避免业务代码直连存储 API。
- 为存储内容设计版本号与迁移策略；涉及持久化规范可继续看 [Storage Standard](https://storage.spec.whatwg.org/)。

## 最小示例

### `localStorage`

```js
localStorage.setItem('theme', 'dark')
const theme = localStorage.getItem('theme')
```

- 适合轻量配置，如主题、语言、最近使用偏好。

### `sessionStorage`

```js
sessionStorage.setItem('draft', 'temp value')
const draft = sessionStorage.getItem('draft')
```

- 适合当前页签临时数据，如未提交草稿。

### Cookie

```js
document.cookie = 'token=abc; Path=/; SameSite=Lax'
```

- 适合需要服务端参与的状态，但安全属性必须明确配置。
