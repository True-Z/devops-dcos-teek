# V8 隐藏类与对象存储

## 阅读建议

- 这页重点不是背内部术语，而是理解“对象形状为什么会影响性能”。
- 如果你只关心落地优化，可以直接看“可以怎么优化”。

## 隐藏类是什么

- 隐藏类可以理解为 V8 给“相同对象结构”建立的一份内部描述信息。
- 当多个对象拥有相同字段集合、相同字段添加顺序时，它们更容易复用同一套隐藏类。
- 这样做的价值是：让属性访问更快，给优化编译器更稳定的前提。

## 对象存储的形式是什么

- 可以先把对象理解成两部分：一部分是布局描述，一部分是属性值存储。
- 对 V8 来说，常见会区分：
  - 对象自身直接存放的 in-object properties
  - 放在额外属性存储区里的 properties
  - 数组下标类数据常走 elements 存储

## 隐藏类和对象存储有什么关系

- 隐藏类决定了“这个对象现在长什么样、字段如何布局”。
- 对象存储则是“值实际放在哪里”。
- 两者配合的目标是：让引擎能更快地定位属性，并在热点路径上做更激进的优化。

## 为什么会变慢

| 场景                   | 为什么会影响性能                    |
| ---------------------- | ----------------------------------- |
| 动态增删属性           | 对象形状频繁变化，隐藏类难复用      |
| 同一字段混用多种类型   | 调用点更容易变成多态/超态           |
| 把数组当普通对象乱用   | elements 存储与对象属性存储都变复杂 |
| 热点对象字段顺序不一致 | 破坏稳定布局                        |

## 最小示例

```js
function createUser(id, name) {
  return {
    id,
    name,
    active: true,
  }
}
```

- 如果同类对象都按这个顺序创建，V8 更容易复用同一隐藏类。

## 可以怎么优化

### 1. 保持同类对象字段集合稳定

```js
function createUser(id, name, age) {
  return {
    id,
    name: name ?? '',
    age: age ?? null,
  }
}
```

- 宁可给默认值，也尽量别让字段忽有忽无。

### 2. 保持字段添加顺序一致

- 同类对象在不同分支里按不同顺序挂字段，会降低隐藏类复用概率。

### 3. 热点路径减少 `delete`

- `delete` 会改变对象结构。
- 如果只是想表达“当前没有值”，很多时候设为 `null` 或 `undefined` 更稳。

### 4. 避免把数组当字典对象乱用

- 数组更适合连续下标访问。
- 如果你频繁给数组挂自定义属性，或者制造稀疏数组，优化机会会下降。

## Elements Kind 与数组退化

### Elements Kind 是什么

- 可以把 elements kind 理解成 V8 对“数组里装的是什么、这些下标是否连续”的内部分类。
- 它会影响数组访问路径是否还能保持高效。
- 面试里不需要背所有内部枚举名，但至少要知道：连续、纯数字、无空洞的数组更容易被优化。

### packed 和 holey 的区别

| 形态          | 特征                   | 影响                       |
| ------------- | ---------------------- | -------------------------- |
| packed arrays | 下标连续，没有空洞     | 更容易走高效访问路径       |
| holey arrays  | 中间有空位或被人为拉长 | 访问判断更多，优化机会下降 |

```js
const packed = [1, 2, 3]

const holey = [1, , 3]
holey[10] = 11
```

- `packed` 更稳定。
- `holey` 会让引擎在访问时做更多检查。

### 为什么稀疏数组会退化

- 当数组下标不连续、出现大量空洞，或者被当成字典结构使用时，V8 很难继续把它当作“紧凑数组”处理。
- 这时内部表示会更复杂，读取和遍历成本都会上升。

### 常见触发方式

- 手动制造空位：`[1, , 3]`
- 直接写很大的下标：`arr[100000] = 1`
- 删除数组项：`delete arr[2]`
- 混入非索引属性：`arr.foo = 'bar'`

### 针对数组的优化建议

1. 尽量保持数组连续，不要主动制造空洞。
2. 不要用 `delete` 删除数组项，优先考虑 `splice`。
3. 不要把数组当字典对象挂一堆自定义属性。
4. 热点路径里尽量保持数组元素类型稳定。

### 5. 热点函数输入尽量单态

- 同一个函数反复处理结构完全不同的对象，更容易触发多态与反优化。
- 高频路径的数据结构越稳定，引擎越容易做优化。

## 值表示与类型漂移

### SMI 是什么

- SMI 可以粗略理解成 V8 对“小整数”的一种更轻量表示。
- 当数值能稳定保持在这类表示范围内时，处理成本通常更低。
- 面试里不必背实现位宽，知道“整数稳定、表示更轻”就够了。

### double 是什么

- 当数字不是小整数，或者需要浮点表示时，V8 往往要按 double 这类更通用的数值形式处理。
- 一旦热点数组或热点字段从整数变成浮点，内部表示就可能跟着变化。

### 装箱对象是什么

- 像 `new Number(1)`、`new String('x')`、`new Boolean(false)` 这类写法会产生包装对象。
- 它们不是普通原始值，而是真正的对象，参与比较、属性访问和存储时都更复杂。

```js
console.log(typeof 1) // 'number'
console.log(typeof new Number(1)) // 'object'
```

- 绝大多数业务代码里都不建议主动使用装箱对象。

### 类型漂移是什么

- 类型漂移可以理解成：同一个热点字段、热点数组或热点函数输入，运行过程中频繁切换值类型。
- 例如一开始一直是整数，后面又变成浮点、字符串、对象，这会让优化前提变得不稳定。

```js
const list = [1, 2, 3]
list.push(4.5)
list.push('6')
```

- 这种混用不一定错，但会让引擎更难保持高效路径。

### 针对这些问题怎么优化

| 问题                 | 优化建议                                   |
| -------------------- | ------------------------------------------ |
| 小整数频繁变浮点     | 数值语义保持一致，能用整数就不要混入小数   |
| 热点数组元素类型混杂 | 同一数组尽量保持同类元素                   |
| 字段值类型来回切换   | 同一字段尽量维持稳定类型                   |
| 主动使用装箱对象     | 优先用原始值，不用 `new Number()` 这类写法 |

### 面试短答补充

- SMI、double、装箱对象这些问题，本质都指向同一个核心：让引擎看到更稳定的数据表示。
- 你不需要把内部实现细节全背下来，但要知道“类型越稳定，优化越容易成立”。

## Inline Cache 与调用点稳定性

### Inline Cache 是什么

- Inline Cache 可以理解为 V8 在热点属性访问或方法调用位置做的一层“记忆”。
- 如果同一个位置总是遇到相似对象形状，V8 就更容易缓存访问路径，后续执行也更快。

### monomorphic / polymorphic / megamorphic 是什么

| 状态        | 含义                         | 典型表现               |
| ----------- | ---------------------------- | ---------------------- |
| monomorphic | 调用点长期只看到一种稳定形状 | 最容易优化             |
| polymorphic | 调用点看到少量几种形状       | 还能优化，但复杂度上升 |
| megamorphic | 调用点看到很多种形状         | 优化收益明显下降       |

### 为什么调用点会退化

- 同一个属性访问位置反复接收结构差异很大的对象。
- 同一个热点函数在不同地方被喂入完全不同的数据形态。
- 字段类型、字段顺序、对象来源都不稳定时，inline cache 很难保持简单。

```js
function readName(user) {
  return user.name
}
```

- 如果 `readName` 总是接收同一结构的 `user`，更容易保持 monomorphic。
- 如果一会儿是 `{ name }`，一会儿是数组，一会儿又是别的对象结构，调用点就会逐渐退化。

### 针对 inline cache 怎么优化

1. 热点函数尽量接收结构稳定的数据。
2. 同一调用点避免混入过多不同对象形状。
3. 热点对象的字段顺序、字段类型尽量保持一致。
4. 不要为了“复用一个函数”强行让它吞各种完全不同的数据结构。

### 面试短答补充

- inline cache 的核心不是“缓存值”，而是缓存更稳定的访问路径。
- monomorphic 最理想，polymorphic 还能接受，megamorphic 往往说明调用点已经太混乱了。

## 面试短答

### 隐藏类是什么

- V8 为相同对象结构建立的内部形状描述，用来加速属性访问与优化编译。

### 对象是怎么存的

- 可以粗略理解成：一部分属性直接放对象本身，一部分放额外属性存储区；数组下标类数据通常单独按 elements 方式处理。

### 优化核心是什么

- 让同类对象结构稳定、字段顺序一致、少删字段、少做类型漂移。

### 数组为什么也会影响 V8 优化

- 因为数组不只是“对象的一种写法”，它还有单独的 elements 存储策略。
- 连续、稳定、无空洞的数组更容易保持高效；稀疏数组和类型漂移会让优化空间下降。
