# V8 速查要点

## 核心定位

- V8 是 JavaScript 执行引擎，直接影响执行性能与内存表现。
- 前端性能优化中，很多问题最终会落到“对象形状、热点函数、垃圾回收”；实战上可继续看 [V8 执行优化方案](/fe/V8-optimize-point)、[V8 隐藏类与对象存储](/fe/v8-hidden-class-storage) 与 [V8 内存泄漏排查方案](/fe/V8-memory-leak-guide)。

## 模块定位

- 这页是 V8 的第一眼速查页，先讲“需要关注什么”，不展开全部底层细节。

## 执行链路速记

| 阶段     | 作用             | 关注点                 |
| -------- | ---------------- | ---------------------- |
| Parse    | 源码解析为 AST   | 启动成本               |
| Ignition | 解释执行字节码   | 首次执行速度           |
| TurboFan | 热点代码优化编译 | 稳定类型信息           |
| Orinoco  | 垃圾回收         | 停顿时间与内存回收效率 |

## 对开发最有价值的认知

- 尽量保持对象结构稳定，减少隐藏类频繁变化。
- 热点路径避免类型来回变化，降低反优化概率。
- 警惕长生命周期引用导致的内存泄漏。

## 实战关注项

- 页面卡顿：先看主线程长任务，再看 GC 停顿。
- 内存增长：先查闭包、缓存、全局引用、事件监听未释放。
- 启动慢：先看首屏脚本体积与初始化逻辑。

## 最小示例

```js
function createPoint(x, y) {
  return {
    x,
    y,
    visible: true,
  }
}
```

- 同类对象保持稳定字段结构，更容易让 V8 做优化，这也是理解运行时性能的最小入口。

## 常见误区

- 过度微优化语法细节，忽略数据结构设计。
- 把所有对象都做动态增删字段，导致优化机会下降。
- 只看平均耗时，不看尾延迟与高峰停顿。
