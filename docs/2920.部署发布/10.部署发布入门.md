# 部署发布入门

## 主模型定位

- 主模型：方法层
- 这页主要回答“怎么做、怎么推进，以及这类工作通常按什么顺序执行。”

## 阅读建议

- 这页重点不是讲完整 CI/CD，而是让你先理解“把代码放到服务器并可用”这条最小链路。

## 核心目标

- 建立最基础的部署心智：代码更新、依赖准备、服务启动、结果验证、必要时回滚。

## 最小部署主线

```text
更新代码 -> 安装依赖 -> 构建或准备产物 -> 启动服务 -> 验证访问 -> 必要时回滚
```

## 部署时最常关心什么

| 方向     | 为什么重要             |
| -------- | ---------------------- |
| 版本     | 知道当前部署的是哪一版 |
| 依赖     | 避免环境和本地不一致   |
| 服务状态 | 确认部署后服务是否正常 |
| 日志     | 出问题时快速定位线索   |
| 回滚     | 发布失败后能及时恢复   |

## 最小示例

```text
拉代码 -> 构建 -> 重启服务 -> 打开页面验证 -> 失败就回滚
```

## 学习建议

1. 先理解部署链路，不追求平台工具细节。
2. 每次部署都要带验证动作。
3. 先会最小发布，再补自动化发布。

## 常见误区

- 只会执行发布命令，不知道每一步在做什么。
- 发布后不验证服务和页面。
- 只想着上线，不准备回滚方案。
