# Windows 与 Linux 基础认知差异

## 主模型定位

- 主模型：认知层
- 这页主要回答“怎么理解这个主题，以及它在运维知识里的位置。”

## 阅读建议

- 这页重点是建立系统认知差异，不是直接教你命令操作。

## 核心目标

- 帮你先分清“运维基础里的操作系统认知”和“运维/Linux 实操”是两层不同知识。

## 一张表看差异

| 维度         | Windows                | Linux                      |
| ------------ | ---------------------- | -------------------------- |
| 主要使用方式 | 图形界面为主           | 命令行和服务管理更常见     |
| 文件路径     | 常见盘符路径，如 `C:\` | 常见根路径，如 `/home`     |
| 权限认知     | 普通用户感知相对弱     | 用户、组、权限更常直接接触 |
| 学习入口     | 日常使用与配置         | 命令、文件、权限、服务     |

## 怎么和运维区分

- 这页属于“运维基础里的操作系统认知”。
- 真正的 Linux 命令、服务部署、日志排查，应放到 `Linux` 或 `运维` 模块。

## 最小示例

```text
Windows 常见是“打开软件使用”
Linux 常见是“进入命令行执行任务”
```

## 学习建议

- 先建立路径、权限、用户、文件系统这些基本认知。
- 再进入 Linux 命令和运维场景。
- 这样后面看部署、服务和日志时更不容易乱。

## 常见误区

- 把“会点 Windows”当成“理解操作系统”。
- 一上来就背大量 Linux 命令，不先建立系统认知。
- 把操作系统基础和运维实践混成同一层。
