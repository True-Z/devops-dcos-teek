# 网络基础入门

## 主模型定位

- 主模型：对象层
- 这页主要回答“在处理什么对象，以及这些对象为什么会影响运维操作。”

## 阅读建议

- 这页重点不是讲完整网络理论，而是让你先理解开发运维场景里最常遇到的网络概念。

## 核心目标

- 建立最小网络排查认知：请求为什么能通、为什么会超时、为什么服务启动了但仍访问不到。

## 最小主线

```text
本机发请求 -> DNS 解析 -> 到目标主机 -> 访问端口 -> 服务响应
```

## 最常见关注点

| 方向     | 为什么重要                   |
| -------- | ---------------------------- |
| IP       | 确认目标主机是谁             |
| 域名/DNS | 确认域名能否正确解析         |
| 端口     | 确认服务是否真的监听         |
| 连通性   | 确认请求能否到达目标         |
| 超时     | 判断是网络慢、服务慢还是没通 |

## 最小示例

```text
页面打不开 -> 先看域名和端口 -> 再看服务是否监听 -> 最后看日志和网络连通性
```

## 学习建议

1. 先学会把“访问失败”拆成 DNS、端口、服务、网络几类问题。
2. 先理解概念，再记命令。
3. 网络学习和日志、服务学习要一起看。

## 常见误区

- 只说“网络有问题”，却说不清是哪个环节有问题。
- 只盯命令输出，不理解 IP、域名、端口的关系。
- 服务启动失败和网络不通混在一起。
