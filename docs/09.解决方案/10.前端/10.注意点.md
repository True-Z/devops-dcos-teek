## vue

- 组件 template 中最好有且只有一个主节点（注释也算），防止组件透递过来的属性无法被多节点（无法确定那个节点）接收。

```vue
<template>
  <div class="page-root">
    <slot />
  </div>
</template>
```

- 最小实践就是固定一个明确根节点，避免属性透传和动画包裹时出现异常。

## vue typescript

- 由于`.vue` SFC 虚拟文件（Volar 会生成中间 TS 文件），所以导致部分需要推导的字段推导异常，常见的有（props、name），所以在命名时需要避免。

| 场景             | 建议         | 原因                |
| ---------------- | ------------ | ------------------- |
| `props` 推导异常 | 显式声明类型 | 减少模板推导偏差    |
| 组件名识别异常   | 避免模糊命名 | 降低 Volar 推导冲突 |

## 渲染问题

### 组件库

- 使用组件库渲染异常时，多注意 ID 配置是否正确，多半是因为 ID 配置错误导致。

```vue
<FormItem field="userName">
  <Input id="userName" />
</FormItem>
```

- 表单、弹层、表格这类场景，`id`/`field`/`key` 一致性很关键。

### vxe-table

- 响应式数据的改动会触发全量渲染（自定义渲染函数重新执行）的特性，无法避免，但错误的使用方法会导致无意义的刷新。综上所述，在使用时，需要注意：
  - 表格单独配置与全局配置不一致时，样式数据的变化会导致重新全量渲染
  - 表格插槽内不要使用响应式数据，防止数据的变化导致表格渲染
  - 展示数据量过于大时，需要考虑抽离或删除重组件，改为 modal 展示或 format 文本

```ts
const tableOptions = {
  keepSource: true,
}
```

- 最小落地点是先把 `keepSource` 配上，再控制插槽内响应式依赖数量。

## 适配 vben

- 嵌套 modal 时注意，父级 modal 销毁时，子级 modal 会全部销毁。
  - 综上所述，如果需要嵌套 modal，需要在其共同的父级组件中，指定其所有渲染的 modal。
  - 如果组件为全局组件则可是使用一个挂载组件挂载到 app.vue 中，以便后续组件无需声明即可直接使用
- 使用了动画的页面只能有一个 template 下只能有一个根节点（注释也算一个节点）
- 缺少必要的 "keep-source" 参数，这可能会导致出现错误
  - 表格同时开启了编辑能力（`editConfig.enabled: true` + `editRules`），vxe 的这条提示就是针对这种场景：编辑态建议必须开启 `keep-source`。
  - vben 创建的表格都需要 keep-source: true ，其内部操作会涉及修改数据
