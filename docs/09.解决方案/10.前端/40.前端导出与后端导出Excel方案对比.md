# 前端导出与后端导出 Excel 方案对比

## 阅读建议

- 这页重点不是只看“能不能导出”，而是判断 Excel 导出到底该放前端还是后端做。

## 核心结论

- 前端导出更偏“快、轻、即时”。
- 后端导出更偏“稳、适合大数据量、适合留档与批处理”。

## 前端导出常见方案

| 方案             | 常见做法                     |
| ---------------- | ---------------------------- |
| 纯表格导出       | `xlsx` / `sheetjs`           |
| 当前页面数据导出 | 直接把前端已有数据转成工作表 |
| 简单模板导出     | 前端拼列头、行数据、基础样式 |

## 后端导出常见方案

| 方案             | 常见做法                     |
| ---------------- | ---------------------------- |
| 服务端生成工作簿 | Java / Node / Python 库生成  |
| 模板填充导出     | 固定 Excel 模板 + 数据填充   |
| 异步任务导出     | 大数据量走任务队列、文件存储 |

## 一张表看优缺点

| 维度           | 前端导出 | 后端导出     |
| -------------- | -------- | ------------ |
| 开发速度       | 快       | 较慢         |
| 即时性         | 高       | 中等         |
| 当前页数据导出 | 很适合   | 没必要绕一圈 |
| 大数据量       | 弱       | 更适合       |
| 模板统一性     | 一般     | 更强         |
| 批量导出       | 不适合   | 适合         |
| 权限与审计     | 一般     | 更好做       |
| 文件留档       | 弱       | 更适合       |

## 什么时候更适合前端导出

| 场景         | 为什么                     |
| ------------ | -------------------------- |
| 当前表格导出 | 数据已经在前端，直接转更快 |
| 临时下载     | 不值得额外走服务端生成链路 |
| 中小数据量   | 浏览器还能承受             |

## 什么时候更适合后端导出

| 场景     | 为什么                     |
| -------- | -------------------------- |
| 大数据量 | 前端内存和性能压力大       |
| 复杂模板 | 服务端更适合做统一模板控制 |
| 异步导出 | 用户不必一直等在页面上     |
| 需要留档 | 服务端更好做文件管理和审计 |

## 最小判断

```text
导当前页小表格 -> 前端
导大量数据或正式报表 -> 后端
```

## 实战建议

1. 后台简单列表导出，优先前端。
2. 大数据量、复杂模板、正式报表，优先后端。
3. 如果用户只需要“导出当前筛选结果”，先看前端数据量能不能承受。
4. 如果未来要支持批量和留档，尽量一开始就考虑后端方案。

## 常见误区

- 觉得 Excel 导出天然就该前端做。
- 前端一次性塞大量数据，导致浏览器卡死。
- 明明是正式报表场景，却只图快放前端导出。
