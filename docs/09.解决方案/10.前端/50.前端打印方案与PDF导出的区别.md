# 前端打印方案与 PDF 导出的区别

## 阅读建议

- 这页重点不是问“都能出文件为什么还要区分”，而是判断什么时候只需要打印，什么时候必须做真正的 PDF 导出。

## 核心结论

- 前端打印更偏“浏览器展示 -> 打印输出”。
- PDF 导出更偏“生成一个稳定文件”。

## 前端打印是什么

- 常见做法是：
  - `window.print()`
  - 配合打印样式 `@media print`
- 它本质上还是浏览器在渲染页面，只是换成打印介质输出。

## PDF 导出是什么

- 常见做法是：
  - 前端生成 PDF
  - 后端生成 PDF
- 它本质是在生成一个可下载、可传输、可留档的文件。

## 一张表看区别

| 维度       | 前端打印         | PDF 导出       |
| ---------- | ---------------- | -------------- |
| 核心目标   | 让页面适合打印   | 生成稳定文件   |
| 输出形式   | 浏览器打印流程   | 独立 PDF 文件  |
| 即时性     | 高               | 取决于生成方案 |
| 留档能力   | 弱               | 强             |
| 排版一致性 | 受浏览器打印影响 | 一般更可控     |
| 下载分享   | 不方便           | 方便           |

## 什么时候更适合打印

| 场景             | 为什么             |
| ---------------- | ------------------ |
| 页面内容直接打印 | 不需要额外生成文件 |
| 内部临时打印     | 只求快速输出       |
| 简单票据、清单   | 浏览器打印就够用   |

## 什么时候更适合 PDF

| 场景             | 为什么               |
| ---------------- | -------------------- |
| 需要发给别人     | PDF 更方便传输       |
| 需要留档         | 文件更稳定           |
| 需要统一版式     | PDF 更适合做固定模板 |
| 需要多次下载复用 | 文件形式更合适       |

## 最小判断

```text
只想当前页面快速打出来 -> 打印
想生成正式文件保存和发送 -> PDF
```

## 实战建议

1. 页面内部临时打印，优先打印样式方案。
2. 正式业务文件，优先 PDF 导出。
3. 如果两者都要，可以先做打印版，再评估是否需要补 PDF 文件流。

## 常见误区

- 以为打印和 PDF 导出完全一样。
- 明明要留档和发送，却只做打印页面。
- 明明只是临时打印，却上来就做复杂 PDF 生成链路。
