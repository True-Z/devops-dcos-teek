## 部署对象

当前文档针对 `D:\1024.DevOps\@nsdk\apps\web-ele` 的部署流程，项目基于 `@nsdk + vben` 的前端管理端体系。

## 当前主用部署方式

当前主用方式为 `rsync` 上传构建产物。

| 项目         | 说明                   | 配置位置             |
| ------------ | ---------------------- | -------------------- |
| 主用部署命令 | `deploy:web:test`      | `@nsdk/package.json` |
| 一键发布命令 | `release:web:test`     | `@nsdk/package.json` |
| 产物目录     | `./apps/web-ele/dist/` | `@nsdk/package.json` |

## 构建命令

在 `@nsdk` 根目录执行：

```bash
pnpm run build:test
```

`build:test` 会触发 `web-ele` 的 Vite 测试环境构建，产物输出到 `apps/web-ele/dist`。

## 最小执行流程

```bash
# 1. 进入仓库根目录
pnpm run build:test

# 2. 确认产物存在
dir .\apps\web-ele\dist

# 3. 执行发布
pnpm run deploy:web:test
```

- 如果你希望“一条命令完成”，直接执行 `pnpm run release:web:test` 即可。

## rsync 部署命令解析

当前命令（根 `package.json`）：

```bash
set "PATH=C:\msys64\usr\bin;%PATH%" && rsync -az --delete --info=progress2 -e "ssh -i C:/Users/True/.ssh/id_rsa" ./apps/web-ele/dist/ ubuntu@118.24.41.2:/
```

参数说明：

| 参数               | 含义                   | 注意点                     |
| ------------------ | ---------------------- | -------------------------- |
| `-a`               | 归档模式，保留文件属性 | 适合静态资源目录同步       |
| `-z`               | 传输压缩               | 网络较慢时更有效           |
| `--delete`         | 删除远端多余文件       | 有清理风险，需确认目标路径 |
| `--info=progress2` | 输出进度               | 便于观察大文件上传         |
| `-e "ssh -i ..."`  | 指定 SSH 与私钥        | 依赖本机私钥路径           |

### windows 环境下需下载软件

#### MSYS2

MSYS2 是一个给 Windows 用的“类 Linux 工具环境”

1. 安装 MSYS2：`https://www.msys2.org/`

2. 打开 MSYS2，执行命令

   ```sh
   # 更新包
   pacman -Syu
   # 下载连接软件
   pacman -S --needed rsync openssh
   ```

3. 将以下目录加入系统 path（按你的安装路径）：

   C:\msys64\usr\bin

   C:\msys64\64\bin\rsync.exe

4. 重新打开终端，验证：

   ```sh
   rsync --version
   ssh -V
   ```

## 一键发布流程

推荐在 `@nsdk` 根目录执行：

```bash
pnpm run release:web:test
```

流程为：

1. 执行 `build:test`
2. 执行 `deploy:web:test`（rsync 上传）

## 环境变量与部署关联

重点关注 `apps/web-ele/.env.production`：

| 变量                   | 作用             | 部署影响                |
| ---------------------- | ---------------- | ----------------------- |
| `VITE_BASE`            | 应用基础路径     | 子路径部署时必须匹配    |
| `VITE_GLOB_API_URL`    | 后端接口地址     | 决定线上请求目标        |
| `VITE_REQUEST_TIMEOUT` | 请求超时         | 影响弱网容忍度          |
| `VITE_ROUTER_HISTORY`  | 路由模式         | `hash` 对静态部署更友好 |
| `VITE_SOURCE_MAP`      | sourcemap 开关   | 影响调试与包体积        |
| `VITE_ARCHIVER`        | 是否压缩归档产物 | 影响发布附加产物        |
| `VITE_USE_MINIFY`      | 是否压缩代码     | 影响体积与调试可读性    |

## 部署前检查表

| 检查项           | 检查内容                             | 目的             |
| ---------------- | ------------------------------------ | ---------------- |
| 构建是否成功     | `dist` 目录已生成                    | 防止空目录上传   |
| 接口地址是否正确 | `VITE_GLOB_API_URL` 是否指向目标环境 | 防止打错环境     |
| SSH 是否可用     | 私钥路径、远端权限正常               | 防止上传失败     |
| 目标路径是否确认 | 尤其注意 `--delete`                  | 防止误删远端文件 |

## 部署注意点

- `vite.config.mts` 的 `server.proxy` 仅在本地开发生效，线上代理需由服务器或网关处理。
- `rsync --delete` 会删除远端目标中本地不存在的文件，执行前必须确认目标目录。
- 私钥路径 `C:/Users/True/.ssh/id_rsa` 与本机绑定，换机需同步密钥或修改命令。
- 当前目标路径配置为服务器根路径 `:/`，建议后续固定为明确业务目录，避免误覆盖。

## 备用方案

当前仓库同时存在备用部署方案：

- `scripts/deploy.js`：Node + `ssh2` 的 SFTP 上传方式（支持 `--with-build`）。
- `scripts/deploy/Dockerfile` + `nginx.conf`：容器化部署参考。

若后续切换为 Docker 方案，需先核对 Dockerfile 中构建产物路径是否与 `web-ele` 当前实际目录一致。
