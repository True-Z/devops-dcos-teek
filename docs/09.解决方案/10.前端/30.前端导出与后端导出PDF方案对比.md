# 前端导出与后端导出 PDF 方案对比

## 阅读建议

- 这页重点不是只看“能不能导出”，而是判断什么场景更适合前端导出，什么场景必须后端导出。

## 核心结论

- 前端导出更偏“快、轻、所见即所得”。
- 后端导出更偏“稳、统一、适合正式文件”。

## 前端导出常见方案

| 方案       | 常见做法              |
| ---------- | --------------------- |
| 页面截图型 | `html2canvas + jsPDF` |
| 打印型     | `window.print()`      |
| 纯数据型   | 前端库直接拼 PDF      |

## 后端导出常见方案

| 方案        | 常见做法                      |
| ----------- | ----------------------------- |
| HTML 转 PDF | 模板 + Puppeteer / Playwright |
| 模板引擎    | 固定版式渲染                  |
| 报表服务    | 批量导出、异步导出            |

## 一张表看优缺点

| 维度         | 前端导出 | 后端导出             |
| ------------ | -------- | -------------------- |
| 开发速度     | 快       | 较慢                 |
| 即时性       | 高       | 中等                 |
| 所见即所得   | 强       | 一般要额外做模板对齐 |
| 排版稳定性   | 一般     | 高                   |
| 多页复杂排版 | 较弱     | 更强                 |
| 批量导出     | 不适合   | 适合                 |
| 留档审计     | 弱       | 更适合               |
| 权限控制     | 一般     | 更好做               |

## 什么时候更适合前端导出

| 场景         | 为什么                       |
| ------------ | ---------------------------- |
| 当前页面导出 | 页面已经渲染好了，直接导更快 |
| 临时下载     | 不值得走后端完整导出链路     |
| 简单报表     | 样式复杂度和分页要求不高     |

## 什么时候更适合后端导出

| 场景                 | 为什么                   |
| -------------------- | ------------------------ |
| 正式单据             | 版式、稳定性要求高       |
| 合同 / 发票 / 报价单 | 需要统一模板、水印、留档 |
| 多页复杂内容         | 分页和排版更好控         |
| 批量导出             | 更适合异步任务和文件生成 |

## 最小判断

```text
要快、要当前页面效果 -> 前端导出
要稳、要正式、要留档 -> 后端导出
```

## 实战建议

1. 管理后台里的简单页面导出，优先前端。
2. 正式业务文件，优先后端。
3. 如果既要预览又要正式导出，可以前端预览、后端生成最终文件。

## 常见误区

- 只因为前端好做，就把正式单据也放前端导出。
- 只看能不能出 PDF，不看分页、字体、留档和权限要求。
- 页面导出方案直接硬套到批量导出场景。
