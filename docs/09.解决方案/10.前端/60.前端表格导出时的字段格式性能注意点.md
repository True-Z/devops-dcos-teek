# 前端表格导出时的字段格式性能注意点

## 阅读建议

- 这页重点不是讲“怎么导出”，而是讲导出前最容易忽略的三个点：字段、格式、性能。

## 核心结论

- 表格导出真正容易出问题的，不是按钮本身，而是字段组织、格式处理和大数据量性能。

## 字段层面要注意什么

| 问题         | 要做什么               | 为什么                             |
| ------------ | ---------------------- | ---------------------------------- |
| 字段过多     | 只导业务真正需要的字段 | 导出不是把页面所有数据都搬出去     |
| 字段名不友好 | 单独做导出列名映射     | 页面字段名和导出表头不一定适合用户 |
| 嵌套结构复杂 | 先整理成扁平结构       | Excel 更适合扁平数据               |

## 格式层面要注意什么

| 问题     | 要做什么         | 为什么                            |
| -------- | ---------------- | --------------------------------- |
| 时间格式 | 导出前统一格式化 | 防止导出后难读                    |
| 金额格式 | 保留统一小数规则 | 防止金额展示混乱                  |
| 状态值   | 枚举转成可读文案 | 不要直接导出内部代码值            |
| 空值     | 统一空值展示规则 | 避免出现一堆 `null` / `undefined` |

## 性能层面要注意什么

| 问题           | 要做什么               | 为什么                 |
| -------------- | ---------------------- | ---------------------- |
| 数据量大       | 分页导出或改后端导出   | 浏览器内存和卡顿风险高 |
| 页面主线程卡顿 | 导出前尽量简化转换逻辑 | 避免界面冻结           |
| 一次导出太多列 | 先裁字段               | 列越多处理越重         |

## 最小示例

```ts
const exportRows = list.map((item) => ({
  姓名: item.name,
  状态: statusMap[item.status],
  金额: formatAmount(item.amount),
  创建时间: formatDate(item.createdAt),
}))
```

## 实战建议

1. 页面展示字段和导出字段分开设计。
2. 导出前先做一层“导出数据转换”。
3. 大数据量场景优先评估是否应该后端导出。
4. 导出前优先保证“用户能看懂”，再追求和页面完全一致。

## 常见误区

- 直接拿页面数据原样导出。
- 枚举值、时间值、金额值不做格式化。
- 大数据量还坚持前端一次性导出。
