## 目标

统一提交信息格式，让变更历史可检索、可追踪、可自动化处理。

## 工具作用

| 工具         | 核心作用                         | 典型场景       | 在 @nsdk 中的价值                      |
| ------------ | -------------------------------- | -------------- | -------------------------------------- |
| `commitlint` | 校验 commit message 是否符合约定 | 提交时校验     | 保证提交信息结构一致，方便生成变更日志 |
| `cz-git`     | 提供交互式提交引导               | 开发者提交代码 | 降低记忆成本，减少无效或混乱提交       |

## 配置与生态清单

### commitlint

- 作用：校验提交信息结构（type/scope/subject）是否符合团队规范。
- 当前项目配置入口：`internal/lint-configs/commitlint-config/index.mjs`。
- 常见生态插件：`@commitlint/cli`、`@commitlint/config-conventional`、`@commitlint/prompt-cli`。
- 建议最小命令：`pnpm commitlint --from HEAD~1 --to HEAD --verbose`。

```js
export default {
  extends: ['@commitlint/config-conventional'],
}
```

- 这是最小可用配置，先保证提交格式统一，再逐步细化类型与 scope。

### cz-git

- 作用：提供交互式提交向导，降低手写 commit message 负担。
- 当前项目配置入口：根 `package.json` 的 `config.commitizen.path`。
- 常见生态插件：`commitizen`、`cz-git`、`czg`（可选命令封装）。
- 建议最小命令：`pnpm cz`。

```json
{
  "config": {
    "commitizen": {
      "path": "node_modules/cz-git"
    }
  }
}
```

- 这样接入后，团队成员只要执行 `pnpm cz` 就能按提示完成提交。
