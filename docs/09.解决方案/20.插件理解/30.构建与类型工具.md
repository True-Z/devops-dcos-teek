## 目标

统一构建行为与类型约束，降低环境差异带来的问题。

## 工具作用

| 工具/配置           | 核心作用                 | 典型场景             | 在 @nsdk 中的价值                |
| ------------------- | ------------------------ | -------------------- | -------------------------------- |
| `typescript`        | 提供静态类型系统         | 开发与构建期类型检查 | 提前暴露类型问题，提升重构安全性 |
| `vite`              | 提供开发服务器与构建能力 | 本地开发、产物打包   | 提升开发效率，统一工程构建入口   |
| `@nsdk/tsconfig`    | 提供共享 TS 配置基线     | 多包工程复用         | 保持各子工程配置一致，减少漂移   |
| `@nsdk/vite-config` | 提供共享 Vite 配置能力   | 多应用构建复用       | 统一项目构建策略，降低重复维护   |

## 配置与生态清单

### typescript

- 作用：编译期类型约束与类型推导，提高重构安全性。
- 当前项目配置入口：`internal/tsconfig/*.json` 与应用侧 `tsconfig.json` 继承链。
- 常见生态插件：`typescript`、`vue-tsc`、`@vue/tsconfig`。
- 建议最小命令：`pnpm vue-tsc --noEmit --skipLibCheck`。

```json
{
  "extends": "@nsdk/tsconfig/base.json"
}
```

- 先继承统一基线，再按项目覆盖少量差异配置。

### vite

- 作用：统一本地开发、构建、插件扩展能力。
- 当前项目配置入口：`apps/web-ele/vite.config.mts` 与 `internal/vite-config/src`。
- 常见生态插件：`@vitejs/plugin-vue`、`unplugin-auto-import`、`unplugin-vue-components`、`unplugin-icons`、`vite-plugin-svg-icons`。
- 建议最小命令：`pnpm vite --mode development`、`pnpm vite build --mode production`。

```ts
import { defineConfig } from 'vite'

export default defineConfig({})
```

- 最小 Vite 配置只需要一个空配置即可启动，后续再逐步叠加插件和别名。

### 共享工程配置包

- `@nsdk/tsconfig`：统一 TS 基线（`base/node/web/web-app/library`）。
- `@nsdk/vite-config`：统一 Vite 配置拼装与插件集成。
- `@nsdk/types`：作为类型底座，供多个包复用。

## 接入顺序建议

1. 先接 `typescript/tsconfig`，保证类型系统先可用。
2. 再接 `vite`，跑通开发与构建命令。
3. 最后再接自动导入、图标、组件扫描等增强插件。
