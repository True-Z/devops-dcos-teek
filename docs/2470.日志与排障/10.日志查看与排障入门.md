# 日志查看与排障入门

## 主模型定位

- 主模型：对象层
- 这页主要回答“在处理什么对象，以及这些对象为什么会影响运维操作。”

## 阅读建议

- 这页面向开发者入门运维，重点不是一次看懂所有日志系统，而是先学会从日志里定位问题线索。

## 核心目标

- 建立最小排障心智：先看现象，再看日志，再结合时间线和报错关键词判断问题方向。

## 最小排障主线

```text
看到问题 -> 找到对应时间 -> 看错误日志 -> 抓关键词 -> 判断服务/权限/网络/配置问题
```

## 常见关注点

| 方向     | 常看什么                        |
| -------- | ------------------------------- |
| 服务日志 | 应用报错、启动失败、异常堆栈    |
| 系统日志 | 权限、磁盘、网络、进程异常      |
| 时间线   | 问题发生前后做了什么            |
| 关键词   | `error`、`failed`、`timeout` 等 |

## 最小示例

```text
服务打不开 -> 查看最近日志 -> 找到 error / timeout -> 再判断是配置还是网络
```

## 学习建议

1. 先学会从“最近发生了什么”切入。
2. 看到错误词时先不急着修，先判断它属于哪类问题。
3. 一边看日志，一边记录高频报错词。

## 常见误区

- 只看最后一行报错，不看上下文。
- 一看到英文报错就跳过，不先抓关键词。
- 没有时间线意识，排障过程很乱。
