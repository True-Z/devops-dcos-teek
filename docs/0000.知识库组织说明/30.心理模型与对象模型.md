# 三层模型与面试视角

为了让知识库既方便组织，又方便后续复习和表达，内容不再只按“心理模型 / 对象模型”两分，而统一收敛成三层模型，再补一个面试视角；对不属于知识型内容的部分，再单独使用记录型模型理解。

## 三层模型总表

| 层     | 是什么                         | 为了什么                         | 典型内容                           | 典型 title                                         |
| ------ | ------------------------------ | -------------------------------- | ---------------------------------- | -------------------------------------------------- |
| 认知层 | 解释“怎么理解一个领域”         | 搭地图、定边界、定顺序           | 是什么、分类、路径、边界、规则     | `运维是什么`、`分类全览`、`学习路径`               |
| 对象层 | 解释“实际在处理什么对象或主题” | 落对象、落场景、落操作           | 文件、权限、服务、日志、部署、资源 | `权限与用户`、`服务管理`、`日志与排障`、`部署发布` |
| 方法层 | 解释“怎么学、怎么做、怎么推进” | 承接学习方法、执行方法、复盘方法 | 计划、执行、复盘、方法论           | `学习方法`、`执行节奏`、`复盘方式`                 |

## 记录型模型

记录型模型不属于三层模型本身，它主要用于承接“发生了什么、怎么感受、最后留下什么”的内容。

它更适合：

- 经历记录
- 感受表达
- 事后提炼

这类内容不强行套入认知层、对象层、方法层，而是按记录逻辑组织；只有当提炼结果已经稳定、可复用时，才回流到知识型内容。

## 认知层

认知层解决的是“怎么理解”。

它主要用于：

- 解释一个领域是什么。
- 解释为什么这样分类。
- 解释先学什么、后学什么。
- 帮助读者先建立一张认知地图。

这类内容更接近：

- 是什么
- 分类全览
- 学习路径
- 原理理解
- 差异理解

### 适合写哪些二级标题

| 二级标题                | 用途                   |
| ----------------------- | ---------------------- |
| `这是什么`              | 先定义主题             |
| `为什么这样理解`        | 说明存在意义           |
| `分类方式` / `组成方式` | 说明怎么拆             |
| `边界与区别`            | 说明和相近主题怎么区分 |
| `推荐阅读顺序`          | 给顺序                 |
| `延伸阅读`              | 给后续入口             |

## 对象层

对象层解决的是“在处理什么”。

它主要用于：

- 承接真正会被操作、观察、排查、维护的对象。
- 让内容从抽象理解落到具体对象。

这类内容更接近：

- 文件与目录
- 权限与用户
- 服务管理
- 进程与资源
- 网络连通
- 日志与排障
- 部署发布

### 适合写哪些二级标题

| 二级标题         | 用途             |
| ---------------- | ---------------- |
| `这是什么`       | 定义对象或主题   |
| `为什么会遇到它` | 说明使用场景     |
| `关键点`         | 提炼核心内容     |
| `常见场景`       | 落到真实使用     |
| `最小示例`       | 给最小可执行理解 |
| `延伸阅读`       | 给相关入口       |

## 方法层

方法层解决的是“怎么学、怎么做、怎么推进”。

它主要用于：

- 承接学习方法、执行方法和复盘方法。
- 解释如何把内容真正学起来、用起来、推进下去。

这类内容更接近：

- 学习路径
- 目标拆分
- 执行节奏
- 复盘方式

### 适合写哪些二级标题

| 二级标题   | 用途               |
| ---------- | ------------------ |
| `适用场景` | 说明这套方法何时用 |
| `推荐步骤` | 给出执行顺序       |
| `常见误区` | 说明容易偏掉的地方 |
| `执行建议` | 给出实际推进方式   |
| `延伸阅读` | 给后续方法入口     |

## 面试视角

面试不是新的基础层，而是一种输出视角。

它的作用不是替代三层模型，而是把认知层、对象层、方法层里的内容压缩成更容易复习、表达、回答的形式。

也就是说：

- 知识库内部可以按三层模型细分组织。
- 真正复习或表达时，再按面试视角把内容压缩成更短的输出结构。

## 最小判断法

- 如果内容主要在回答“怎么理解”，优先归入认知层。
- 如果内容主要在回答“在处理什么对象”，优先归入对象层。
- 如果内容主要在回答“怎么学、怎么做、怎么推进”，优先归入方法层。
- 如果内容是在服务复习、表达、答题，不单独成基础层，而作为面试视角使用。
- 如果内容主要在记录经历、感受、留存体会，不优先放入三层模型，而按记录型模型处理。

## 现有一级分类的粗分方式

这一步不是给一级分类永久定性，而是先帮助判断当前内容更偏哪一层。

| 一级分类              | 当前更偏           | 说明                                                   |
| --------------------- | ------------------ | ------------------------------------------------------ |
| `0000.知识库组织说明` | 认知层             | 用于解释知识库怎么组织、怎么理解、怎么归位             |
| `00.编程`             | 对象层为主         | 主要承接前端、数据库、算法、方案等具体主题             |
| `2000.运维`           | 混合，但对象层为主 | 既有认知，也有大量对象、场景、方案内容                 |
| `10.工程协作`         | 对象层为主         | 主要承接 IDE、版本控制、包管理器等具体对象             |
| `12.脚本工具`         | 对象层为主         | 主要承接脚本工具与可复用工具流程                       |
| `80.学习与执行`       | 方法层为主         | 主要承接目标、计划、路径、执行与复盘                   |
| `9999.经历记录`       | 记录型模型         | 更偏经历、感受与提炼，不应强行套入认知 / 对象 / 方法层 |

## 使用建议

- 先用认知层、对象层、方法层把内容粗分，再决定目录是否要合并或重定义。
- 不要求一个一级分类只能属于一种层，但要先判断它当前“主承载”的是哪一层。
- 如果一个分类内部同时存在多层内容，就需要继续拆层，避免总览、说明、对象和方法混在一起。
- 如果内容主要是留档、感受、事后提炼，则优先按记录型模型组织，不硬套三层模型。
