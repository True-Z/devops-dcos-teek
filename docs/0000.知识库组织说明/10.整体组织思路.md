# 整体组织思路

这套知识库不是按“想到什么就写什么”的方式堆内容，而是先约定统一的组织方式，再把内容放到合适的位置。

这样做的目标有两个：

- 让写的人知道一篇内容该放哪里。
- 让看的人能快速理解这篇内容属于什么层级、解决什么问题。

## 核心思路

- 用目录层级表达“内容在知识库中的位置”。
- 用文件分工表达“这篇内容承担什么职责”。
- 用统一规则降低后续新增内容时的混乱感。

## 这套组织方式在解决什么问题

- 避免同类内容分散到多个不相关位置。
- 避免目录页、简介页、正文页混着写同一类内容。
- 避免后续分类越扩越乱，看的人找不到入口。

## 内容如何归位

- 先判断这篇内容主要在回答“怎么理解”，还是“在处理什么对象”。
- 如果是在解释结构、分类、边界、顺序，优先归入承担理解职责的说明页、总览页或认知型分类。
- 如果是在讲对象、问题、操作、方案，优先归入具体主题页。
- 如果某个主题内容继续增多，再从四级开始细分，而不是回退去重叠分类。

## 归属冲突如何处理

- 同一主题允许在不同一级分类中都“相关”，但只能有一个主归属。
- 主归属由“这篇内容主要解决什么问题”决定，而不是由词面是否相似决定。
- 其他一级分类如果需要提到它，优先通过目录说明、简介提示或内链引用解决。
- 不在两个一级分类中重复建设完整正文。

## 一个简单例子

- `编程 -> 算法`
  - 主视角是实现、解题、编码应用。
- `运维基础 -> 数据结构与算法`
  - 主视角是理解程序与系统运行所需的最小认知。

两者可以并存，但不能写成两套重复内容。
